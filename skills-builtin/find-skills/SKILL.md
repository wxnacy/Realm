# 技能发现（find-skills）

## ⛔ 本技能的能力边界（先读这一段）

本技能是一个**只读的检索助手**。请严格遵守以下边界：

- 本技能**只产出候选清单**，绝不执行任何安装 / 下载 / 更新操作。
- 本技能**不调用**任何包管理器、包执行器、命令行工具或网络安装脚本。
- 本技能**不发起**任何「把远端内容取回本地再运行」的链条，包括经由管道把远端内容直接交给解释器执行的形态。
- 本技能也不发起「取回后立即执行、不留盘」的即时执行形态，更不涉及把任何内容装到用户级全局位置。
- 本技能不会建议绕过任何确认提示；任何绕过确认的做法都属于越界。
- 本技能的检索动作**只经过 Realm 已有的工具层**（`web_fetch` / `web_search`），不经过终端。
- 安装一律由**用户**在 Realm 内完成：设置 → AI → 技能管理 → 导入。
- 若用户要求你「直接装上」「帮我装好」，回答：本技能不能安装，请走上面的导入入口。

**关于本节措辞的说明**：本节刻意**不逐条列举具体的命令名**，只描述语义边界 —— 逐条列举命令名会让模型把那些命令当作可执行示例照搬。判定标准是：**每一行文字被模型执行后，应当只产生一次工具调用**（`web_fetch` / `web_search`），而不是在终端里多出一条命令。若某行文字会让终端里多出命令，那一行就是越界。

## 何时使用

在以下场景使用本技能：

- 用户问「有没有能做 X 的技能？」「有没有现成的技能可以帮我做 Y？」
- 用户说「帮我找个技能」「搜一下技能」
- 用户描述了一个需求，想知道开源生态里是否已有对应的 Agent 技能

不适用：用户想**创建**一个全新技能 —— 请引导到 `skill-creator` 技能。

## 检索流程（三步，顺序固定）

### 第 1 步：用 `web_fetch` 取结构化候选

调用 `web_fetch` 请求 GitHub 的仓库搜索接口，参数固定：

- `url`：`https://api.github.com/search/repositories?q=<关键词>&sort=stars&order=desc&per_page=5`
- `maxLength`：**必须显式传 `30000`**

> ⚠️ 必须显式传 `maxLength`：`web_fetch` 的默认上限是 12000 字符，而搜索接口的响应包含大量嵌套字段（`owner` 对象、各类 `*_url`），`per_page=5` 的响应就可能超过默认上限而被截断，导致候选信息不完整。

关键词用英文更有效（生态里的仓库名与描述以英文为主）。可用空格组合多个词，例如 `agent skill browser`。

### 第 2 步：逐条 `web_fetch` 仓库页核验

对第 1 步返回的每一个候选，**逐条**用 `web_fetch` 打开其仓库页（`html_url`）核验。核验不合格的候选直接丢弃，不要降级输出。

### 第 3 步：仅在第 1 步失败时用 `web_search` 兜底

只有当第 1 步**失败**（403 触达配额上限、网络错误、返回体无法解析）时才改用 `web_search` 做模糊定位。**不要**在正常情况下用 `web_search` 替代第 1 步 —— 搜索结果无法给出可信的许可证与活跃度字段。

## 检索端点（唯一允许的端点）

唯一允许的检索端点是 GitHub 的**仓库搜索**接口：

```
https://api.github.com/search/repositories?q=<查询串>&sort=stars|updated&order=desc&per_page=<1-100>
```

可用的 `q=` 限定符（均无需鉴权）：

| 限定符 | 含义 | 示例 |
|--------|------|------|
| `topic:<name>` | 按仓库主题标签过滤 | `topic:agent-skills` |
| `in:name` | 匹配仓库名 | `in:name skill` |
| `in:description` | 匹配仓库描述 | `in:description "agent skill"` |
| `stars:>N` | 星标数下限 | `stars:>100` |
| `language:` | 主要语言 | `language:python` |

排序参数：`sort=stars`（按星标）或 `sort=updated`（按最近更新）；`order=desc`；`per_page` 取 1–100。

**两条硬性限制：**

1. **代码搜索接口不可用。** GitHub 的代码搜索接口需要鉴权，Realm 的 `web_fetch` 不带凭据，调用它只会拿到 401。**不要**使用它，也不要根据它反推「技能在仓库内的路径」—— 本技能的输出里**不要求**该字段。
2. **搜索配额是 10 次/分钟。** 一次请求要取够候选（`per_page=5` 起），不要为同一个意思反复变换查询串重试。

## 核验规则（不核验不得输出）

第 2 步的核验必须完成以下三项，任一项无法确认即**丢弃该候选**：

1. **确认技能文件存在**：打开仓库页，确认其中存在 `SKILL.md`（通常位于 `skills/<name>/SKILL.md` 或仓库根的 `<name>/SKILL.md`）。
2. **核出许可证**：确认仓库或技能目录内存在 `LICENSE` / `LICENSE.txt`，读出许可证名称。

   > ⚠️ **不要只信搜索接口返回的 `license` 字段。** 实测该字段经常给出 `None`，但仓库内其实有许可证文件（许可证放在子目录里时，仓库级识别会失效）。必须打开仓库页确认。

3. **确认活跃度**：读取最近一次提交日期或 `pushed_at`，判断是否仍在维护。

核验失败、或只拿到搜索结果摘要而没有打开仓库页时，**不得输出**该候选。

## 输出格式（候选清单）

核验通过后，输出一份候选清单。每条固定包含以下字段：

| 字段 | 说明 |
|------|------|
| 名称 | 技能名（取自 `SKILL.md` 的 `name`） |
| 用途 | 一句话说明它能做什么 |
| 仓库 URL | 仓库页面地址 |
| 许可证 | 核验得到的许可证名称；无法确认时写「未知」 |
| 最后活跃时间 | 最近一次提交日期或 `pushed_at` |

字段固定，不做增删。若某条候选的许可证无法确认，把「未知」如实写出，不要猜测。

## 用户如何安装（指路，不是执行）

把清单交给用户后，告知他们导入入口：

**设置 → AI → 技能管理 → 导入**

由用户自己在该入口完成导入。本技能到此结束，**不再对导入过程做任何后续动作**。

## 边界情况

- **搜索接口返回 403（触达配额上限）**：告知用户「检索配额已用完，请稍后再试」，或改用 `web_search` 兜底定位后再逐条核验。
- **搜索无结果**：如实告知用户没有找到匹配的候选，可以建议换用更宽泛的关键词，**不要编造候选**。
- **用户想创建新技能**：引导到 `skill-creator` 技能；本技能不涉及创建，也不给出任何初始化步骤。
- **用户坚持要你「直接装」**：再次说明本技能不执行安装，并重复上面的导入入口。
