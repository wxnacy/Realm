<task type="auto">
  <name>Task 1: 实现拖拽排序核心逻辑</name>
  <files>src/favorites-page.js</files>
  <action>
1. 在 favorites-page.js 顶部引入 fractional-indexing（如果尚未引入）：
   ```js
   const { generateKeyBetween, generateNKeysBetween } = require('fractional-indexing');
   ```
   注意：favorites-page.js 运行在 renderer 进程中（通过 webview），需确认引入方式。
   如果无法直接 require，通过 preload 暴露 generateKeyBetween 和 generateNKeysBetween，
   或在 favorites-page.js 中实现简易的 fractional indexing 生成函数（按 D-12 使用 npm 包）。

2. 在 `renderFavoriteItem(record)` 函数中（第 284 行起）：
   - 为每个收藏项行添加 `draggable="true"` 属性（per D-05）
   - 添加 `data-type="favorite"` 和 `data-id="${record.id}"` 属性
   - 添加 `data-folder-id="${record.folder_id}"` 属性

3. 在 `renderFolderTree(tree, level)` 函数中（第 383 行起）：
   - 为每个文件夹行添加 `draggable="true"` 属性
   - 添加 `data-type="folder"` 和 `data-id="${folder.id}"` 属性
   - 添加 `data-parent-id="${folder.parent_id}"` 属性

4. 在 `setupEventListeners()` 函数中（或新建 `setupDragAndDrop()` 函数），使用事件委托实现拖拽事件：

   a. **dragstart 事件**（委托到列表容器）：
   - 从 `e.target.closest('[draggable]')` 获取拖拽源元素
   - 将拖拽数据存入 `e.dataTransfer`：`{ type: 'favorite'|'folder', id: number, folderId: number }`
   - 设置 `e.dataTransfer.effectAllowed = 'move'`
   - 添加 `.dragging` CSS 类到源元素
   - 存储拖拽源数据到模块级变量 `dragSourceData`

   b. **dragover 事件**（委托到列表容器）：
   - 调用 `e.preventDefault()` 允许放置（关键！）
   - 获取鼠标位置下方的目标元素：`e.target.closest('[data-type]')`
   - 如果目标是文件夹：
     * 检查循环引用：如果拖拽的是文件夹，调用 `isDescendantCheck(dragSourceData.id, targetId)`
     * 如果会形成循环，设置 `e.dataTransfer.dropEffect = 'none'` 并返回
     * 添加 `.drag-over-folder` 类到目标文件夹（per D-06）
   - 如果目标是收藏项或文件夹（同目录排序）：
     * 计算插入位置：`getDragPosition(e, targetEl)` 返回 'top' 或 'bottom'
     * 清除其他元素的 `.drag-over-top` / `.drag-over-bottom` 类
     * 添加对应的 `.drag-over-top` 或 `.drag-over-bottom` 类（per D-07）

   c. **dragleave 事件**（委托到列表容器）：
   - 使用 `e.target.closest('[data-type]')` 获取目标元素
   - 只有当 `relatedTarget` 不在目标元素内时才清除高亮类
   - 移除 `.drag-over-folder`、`.drag-over-top`、`.drag-over-bottom` 类

   d. **drop 事件**（委托到列表容器）：
   - 调用 `e.preventDefault()`
   - 从 `e.dataTransfer.getData('text/plain')` 解析拖拽数据
   - 获取目标元素和插入位置
   - 执行移动逻辑（见下方移动函数）
   - 清除所有拖拽高亮类

   e. **dragend 事件**（委托到列表容器）：
   - 移除源元素的 `.dragging` 类
   - 清除所有 `.drag-over-*` 类
   - 重置 `dragSourceData`

5. 实现 `getDragPosition(e, targetEl)` 函数：
   - 获取目标元素的 boundingClientRect
   - 计算中点 Y 坐标：`rect.top + rect.height / 2`
   - 鼠标在上半部分返回 'before'，下半部分返回 'after'

6. 实现 `isDescendantCheck(sourceId, targetId)` 函数：
   - 复用 Phase 14 的循环引用检测逻辑
   - 在渲染进程中实现简化版本：遍历 targetId 的祖先链，检查是否包含 sourceId
   - 使用 `state.folderTree` 数据在前端判断（避免 IPC 调用）

7. 实现 `executeDragDrop(dragData, targetData, position)` 函数：
   - 根据拖拽类型（单个/文件夹）和目标类型（文件夹/排序位置）执行不同逻辑
   - **拖到文件夹上**（per D-01 跨文件夹移动）：
     * 收藏项：调用 `favoritesApi('move-favorite', { id: dragData.id, folderId: targetData.id })`
     * 文件夹：调用 `favoritesApi('move-folder', { id: dragData.id, parentId: targetData.id })`
   - **同目录排序**（per D-01 同目录排序）：
     * 获取目标文件夹内的所有记录（从 state.currentRecords）
     * 计算新的 sort_order：使用 `generateKeyBetween(beforeKey, afterKey)`
     * 调用 `favoritesApi('update-batch-sort', { items: [{ id: dragData.id, sort_order: newKey }] })`
     * 或 `favoritesApi('update-batch-folder-sort', { folders: [{ id: dragData.id, sort_order: newKey }] })`
   - 操作完成后调用 `loadFavorites()` 刷新列表

8. 实现文件夹在前收藏项在后的排序（per D-02）：
   - 在 `renderFavorites()` 中，将文件夹和收藏项分开渲染
   - 文件夹排在前面，收藏项排在后面
   - 各自按 sort_order ASC 排序
  </action>
