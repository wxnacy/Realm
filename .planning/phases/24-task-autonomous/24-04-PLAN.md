<task type="auto">
  <name>Task 4.1: IPC 通道注册 — action:confirm/action:cancel 双向通信</name>
  <files>main.js, src/preload.js</files>
  <behavior>
    - main.js 注册 action:confirm 和 action:cancel IPC 处理器
    - main.js 实现 requestActionConfirmation 函数，发送确认请求并等待响应
    - preload.js 暴露 actionConfirm 和 actionCancel 方法
    - preload.js 监听 action:request-confirmation 事件并转发到渲染进程
    - 30 秒超时自动取消（per RESEARCH.md 确认 IPC 模式）
  </behavior>
  <action>
    1. 在 main.js 中实现操作确认 IPC 机制：

    a. 顶部新增 pendingActions Map 存储待确认操作的 resolve 回调
    b. 注册 action:confirm IPC 处理器：
       - ipcMain.handle('action:confirm', (event, actionId) => {...})
       - 从 pendingActions 中找到对应 resolve，调用 resolve({ confirmed: true })
       - 返回 { success: true }
    c. 注册 action:cancel IPC 处理器：
       - ipcMain.handle('action:cancel', (event, actionId) => {...})
       - 从 pendingActions 中找到对应 resolve，调用 resolve({ confirmed: false, reason: 'user-cancelled' })
       - 返回 { success: true }
    d. 实现 requestActionConfirmation(actionData) 辅助函数（供 ai-manager.js 调用）：
       - 参数：{ actionId, type, title, description, url, containerId, riskLevel, details }
       - 生成唯一 actionId（如果未提供）
       - 返回 Promise，存储到 pendingActions
       - 通过 mainWindow.webContents.send('action:request-confirmation', data) 发送到渲染进程
       - 30 秒超时：如果 pendingActions 中仍有此 actionId，自动 reject 并清理
    e. 导出 requestActionConfirmation 供 ai-manager.js 使用

    2. 在 src/preload.js 中暴露 API：

    a. contextBridge.exposeInMainWorld('realmAPI', {...}) 中新增：
       - actionConfirm: (actionId) => ipcRenderer.invoke('action:confirm', actionId)
       - actionCancel: (actionId) => ipcRenderer.invoke('action:cancel', actionId)
       - onActionRequestConfirmation: (callback) => {
           ipcRenderer.on('action:request-confirmation', (event, data) => callback(data));
         }
    b. 清理函数：提供移除监听器的方法（参考现有 onContainerSwitched 模式）
  </action>

  </verify>
  <done>

  </done>

<task type="auto">
  <name>Task 4.2: 确认卡片渲染 — 状态机 + UI 交互 + 样式</name>
  <files>src/renderer.js, src/styles/main.css</files>
  <behavior>
    - 收到 action:request-confirmation 事件时在 AI 聊天面板渲染确认卡片
    - 卡片显示操作图标 + 操作描述 + URL + 容器名 + 风险等级标签（per D-06）
    - 确认按钮点击后卡片更新为"执行中..."状态，按钮禁用
    - 取消按钮点击后卡片更新为"已取消"状态（灰色）
    - 操作执行完成后卡片更新为"操作完成 ✓"或"操作失败"状态
    - CAPTCHA 等待时显示等待指示器卡片（per UI-SPEC.md）
  </behavior>
  <action>
    1. 在 src/renderer.js 中实现确认卡片逻辑：

    a. 初始化时注册 IPC 监听器：
       - window.realmAPI.onActionRequestConfirmation((data) => renderConfirmationCard(data))

    b. renderConfirmationCard(actionData) 函数（参考 UI-SPEC.md HTML 结构）：
       - 创建 action-confirm-card 容器
       - 头部：操作图标（根据 type 显示不同 SVG）+ 操作标题 + 风险等级标签
       - 详情区域：目标页面 URL + 容器名称 + 操作描述
       - 操作按钮：取消 + 确认执行
       - 绑定事件：确认 → window.realmAPI.actionConfirm(actionId) + 更新卡片状态
       - 绑定事件：取消 → window.realmAPI.actionCancel(actionId) + 更新卡片状态
       - 插入到 AI 聊天面板的 ai-message-content 容器中

    c. updateCardState(card, state, result?) 函数：
       - pending: 按钮可点击，初始状态
       - executing: 按钮禁用，显示"执行中..."，显示 spinner
       - success: 显示"操作完成 ✓"，绿色勾号
       - error: 显示"操作失败：{error}"，红色 X
       - cancelled: 显示"已取消"，灰色，按钮隐藏

    d. getActionIcon(type) 辅助函数：
       - submit: 提交图标（纸飞机）
       - upload: 上传图标（云上传）
       - payment: 支付图标（信用卡）
       - click: 点击图标（手指）
       - 默认: 操作图标（齿轮）

    e. renderCaptchaWaitingCard() 函数（参考 UI-SPEC.md CAPTCHA/2FA Waiting Indicator）：
       - 显示盾牌/锁图标 + "需要手动验证" 标题
       - 描述："检测到验证码/双因素认证，请在页面中完成验证。完成后我会自动继续。"
       - 显示旋转等待指示器
       - CAPTCHA 完成后更新为"验证完成，继续执行..." 并自动消失
