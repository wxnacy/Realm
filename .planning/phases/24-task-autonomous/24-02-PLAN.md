  <behavior>
    - 工具名称 fill_form，参数格式 { fields: [{ field: "邮箱", value: "test@example.com" }] }（per D-02）
    - 低风险（普通字段填写）直接调用 cdpManager.fillForm 并返回结果
    - 高风险（file upload 字段）通过 IPC 发送确认请求到渲染进程，等待用户确认（per D-07）
    - 字段未找到时返回错误信息和可用字段列表（per D-04）
    - CAPTCHA 检测到时返回特殊标记，提示用户手动操作（per D-14, D-15）
    - 返回格式遵循现有模式：{ content: [{ type: 'text', text: '...' }], details: {...} }
  </behavior>
  <action>
    在 ai-manager.js 的 _buildRealmTools() 方法中新增 fill_form 工具定义。

    工具定义：
    - name: 'fill_form'
    - label: '填写表单'
    - description: '自动填写网页表单字段。支持 input/textarea/select/checkbox/radio 等类型。低风险操作自动执行，文件上传需要用户确认。'
    - parameters: fields 数组，每个元素包含 field（字段名称）和 value（填写值）（per D-02）

    execute 函数实现：
    1. 通过 resolveToolTargetTab 获取当前活跃标签页的 webContentsId
    2. 输入消毒（per D-13）：调用 sanitizeInput(params) 对所有字符串参数消毒，防止 Runtime.evaluate 注入
    3. 调用 cdpManager.fillForm(webContentsId, fields)
    4. 风险评估（per D-07）：检查 fields 中是否包含 file 类型字段
       - 有 file upload → 高风险，调用 requestActionConfirmation 等待用户确认
       - 无 file upload → 低风险，直接执行
    4. CAPTCHA 检测处理（per D-14）：如果 fillForm 返回 captchaDetected，返回提示信息让用户手动操作
    5. 字段未找到处理（per D-04）：将 availableFields 列表包含在错误信息中返回
    6. 返回结果格式化为标准工具返回格式

    requestActionConfirmation 辅助函数（在 ai-manager.js 中实现）：
    - 参数：{ actionId, type, title, description, url, containerId, riskLevel }
    - 通过 mainWindow.webContents.send('action:request-confirmation', data) 发送到渲染进程
    - 返回 Promise，等待用户确认/取消响应
    - 超时 30 秒自动取消
  </action>

<task type="auto" tdd="true">
  <name>Task 2.2: execute_action AI 工具 — 全操作支持 + 风险评估 + 脚本安全检查</name>
  <files>ai-manager.js</files>
  <behavior>
    - 工具名称 execute_action，参数格式 { action: 'click', target: '提交按钮' }（per D-11）
    - 支持 15 种操作类型（per D-10）
    - 低风险（click/scroll/type/select/check/focus/blur/hover/keydown/screenshot/wait_for_element）直接执行
    - 高风险（submit/upload/execute_script）触发确认流程（per D-07）
    - execute_script 参数经过静态分析，检测到危险调用时拒绝执行（per D-13, D-16）
    - 返回操作结果 + 页面变化信息（per D-12）
  </behavior>
  <action>
    在 ai-manager.js 的 _buildRealmTools() 方法中新增 execute_action 工具定义。

    工具定义：
    - name: 'execute_action'
    - label: '执行操作'
    - description: '在当前页面执行操作，如点击按钮、滚动页面、填写输入框等。低风险操作自动执行，表单提交、文件上传、脚本执行需要用户确认。'
    - parameters: action（操作类型）、target（目标元素描述）、options（可选参数，如 type 的文本内容、scroll 的距离等）（per D-11）

    execute 函数实现：
    1. 通过 resolveToolTargetTab 获取当前活跃标签页的 webContentsId
    2. 输入消毒（per D-13）：调用 sanitizeInput(params) 对所有字符串参数消毒，防止 Runtime.evaluate 注入
    3. 风险评估（per D-07）：
       - 高风险操作：submit、upload、execute_script、payment（支付相关）
       - 低风险操作：click、scroll、type、select、check、focus、blur、hover、keydown、screenshot、wait_for_element
       - 支付检测逻辑：检查 target/page URL 是否包含支付关键词（pay、payment、付款、支付、confirm order、place order、下单、结算），或 action 为 submit 且页面包含支付表单特征（金额字段、信用卡字段、支付网关 URL）
    4. 高风险操作确认：
       - submit → 确认卡片显示 "提交表单：确认向 {url} 提交数据？此操作不可撤销。"
       - upload → 确认卡片显示 "上传文件：确认向 {url} 上传文件？"
       - execute_script → 确认卡片显示 "执行脚本：确认在页面中执行脚本？"
       - payment → 确认卡片显示 "支付操作：确认在 {url} 执行支付？请仔细核对金额。"
    5. execute_script 安全检查（per D-13, D-16）：
       - 调用 validateScript(options.script) 进行静态分析
       - 禁止模式：eval, new Function, import(), require(), fs., net., http., child_process, process.
       - 检测到危险调用时直接返回错误，不进入确认流程
       - 仅允许白名单 DOM API：document.querySelector, element.click/scrollIntoView/focus, window.scrollTo, history.back/forward 等
    6. 确认通过后调用 cdpManager.executeAction(webContentsId, action, target, options)
    7. 返回操作结果 + 页面变化信息（per D-12）

    validateScript 辅助函数（在 ai-manager.js 顶部实现）：
    - 参数：script 字符串
    - 返回：{ safe: boolean, reason?: string }
    - 使用正则匹配危险模式列表

    sanitizeInput 辅助函数（在 ai-manager.js 顶部实现，per D-13 输入消毒层）：
    - 参数：params 对象（fill_form/execute_action 的原始参数）
    - 返回：消毒后的参数副本
    - 对所有字符串参数（field、value、target、options 中的字符串字段）执行：
      1. 转义反引号（` → \`）防止模板字符串注入
      2. 移除 ${...} 模板字面量表达式
      3. 转义单引号和双引号防止字符串逃逸
      4. 过滤 null 字节（\x00）
    - 在调用 cdpManager.fillForm/executeAction 之前必须先调用 sanitizeInput
    - 此函数覆盖 D-13 定义的"输入消毒"层，与 validateScript（静态分析层）互补
  </action>

    </automated>
  </verify>
