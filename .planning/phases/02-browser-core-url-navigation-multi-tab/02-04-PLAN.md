<objective>
修复 UAT Phase 02 Test 5/6 失败：URL 输入框回车后 webview 无任何反应。

两个 gap 共享同一根因（诊断已完成，见 02-UAT.md Gaps 段与 .planning/debug/url-input-enter-no-response.md）：

1. **主因**：`window-manager.js` 的 `BrowserWindow.webPreferences` 缺少 `webviewTag: true`。Electron 自 v5 起该选项默认为 false（项目使用 Electron 32.3.3），导致渲染进程 `document.createElement('webview')` 返回无功能的 `HTMLUnknownElement`——不支持导航、不触发任何 webview 事件。
2. **次级 bug**：`src/renderer.js` URL Enter 处理器 `else if (tab)` 分支（行 1574-1580）创建 webview 后未隐藏 `newTabPage`、未将 webview `visibility` 从 `hidden` 切换为 `visible`——即使主因修复，用户仍看不到页面。

Purpose: 仅实施诊断报告明确要求的两个修复，不引入新功能或重构。修复后 UAT Test 5/6 应通过，被阻塞的 Test 7-12 解除阻塞。

Output: 可实际导航的多 Tab 浏览器；02-04-SUMMARY.md
</objective>

<gap_details>
诊断确认的关键事实（摘自 .planning/debug/url-input-enter-no-response.md，已排除的假设不再重复验证）：

- `window-manager.js` 行 25-39 是项目中**唯一**的 BrowserWindow 创建点（main.js 的 `app.on('activate')` 也经 `windowManager.createMainWindow` 间接调用同一函数），webPreferences 仅含 preload / contextIsolation / nodeIntegration / session。
- `node_modules/electron/electron.d.ts` 行 17267 官方类型定义明确：`webviewTag` "Defaults to `false`"；全局 grep 确认项目代码从未设置过 webviewTag。
- URL Enter 处理器本身逻辑正确：事件已绑定、`normalizeUrl` 无 throw 路径、IPC 链路通畅（UAT Test 1-4 通过证明）。
- `createWebviewForTab`（src/renderer.js 行 351-386）创建的 webview 样式为 `visibility: hidden`，且该函数不隐藏 newTabPage、不调用 showWebview——这是次级 bug 的成因。
- `showWebview(tabId)`（src/renderer.js 行 478-502）已存在，职责即切换各 webview 可见性；`switchTab`（行 231-239）已建立"showWebview + 按 tab.url 决定 newTabPage 显隐"的既有模式，本修复遵循该模式。
- webview 安全配置 `WEBVIEW_ATTRIBUTES`（nodeintegration=false 等，D-03）已存在，本次修复**不得**改动。
</gap_details>
