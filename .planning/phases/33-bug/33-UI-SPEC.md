**Behavior (D-01, D-02, D-03, D-04):**

**表格行：**
- 每行显示：复选框、网站域名（带 favicon）、用户名、操作按钮（展开/删除）
- 行高度 40px，hover 态背景 `--bg-hover`
- 点击行（非复选框区域）展开详情

**展开详情 (D-02)：**
- 点击行后在该行下方展开详情区域（`max-height` 过渡动画，200ms ease）
- 详情区显示：密码（默认遮罩 `••••••••`，点击"显示"按钮切换明文）、容器名称、保存时间
- 详情区底部：删除按钮（`--danger-color`）

**搜索 (D-03)：**
- 搜索框位于表格上方，实时过滤（input 事件）
- 按网站域名或用户名匹配（不区分大小写）
- 无匹配时显示"未找到匹配的凭据"

**批量删除 (D-04)：**
- 复选框选中后显示批量操作栏（与下载面板批量操作栏样式一致）
- 显示已选数量
- "删除所选"按钮：弹出确认对话框
- "取消选择"按钮：清除所有选中状态
- 全选复选框：选中/取消选中所有可见行

**Sizing:** 表格宽度 100%，列宽比例 checkbox(40px) | website(40%) | username(35%) | actions(剩余)。

**States:**
1. **Loading:** 表格体显示骨架行（3 行灰色占位）
2. **Populated:** 显示凭据列表
3. **Empty:** 显示空状态图标和提示文案
4. **Filtered (no match):** 显示"未找到匹配的凭据"
5. **Row expanded:** 行高亮 + 下方展开详情区
6. **Batch selected:** 批量操作栏滑入显示

## Interaction Specifications

### 凭据管理交互 (AF-04)

**数据加载 (D-01)：**
1. 用户切换到"自动填充"页面
2. 调用 `GET /api/credentials/list` 获取当前容器的凭据列表
3. 渲染表格行，每行包含：复选框、域名（带 favicon）、用户名、操作按钮

**搜索过滤 (D-03)：**
1. 用户在搜索框输入关键词
2. 实时过滤表格行（input 事件，300ms 防抖）
3. 匹配域名或用户名（不区分大小写）
4. 无匹配显示空状态

**展开详情 (D-02)：**
1. 用户点击表格行（非复选框区域）
2. 该行下方展开详情区（`max-height` 过渡，200ms ease）
3. 详情区显示：密码（遮罩）、容器名称、保存时间
4. 点击"显示"按钮切换密码明文/遮罩
5. 再次点击行或点击其他行时收起

**单条删除：**
1. 用户点击行的删除按钮或展开详情中的删除按钮
2. 弹出确认对话框："确定要删除 {domain} 的凭据吗？"
3. 确认后调用 `POST /api/credentials/delete`，刷新列表

**批量删除 (D-04)：**
1. 用户选中一个或多个复选框
2. 批量操作栏滑入显示，显示已选数量
3. 点击"删除所选"：弹出确认对话框
4. 确认后调用 `POST /api/credentials/batch-delete`，刷新列表
5. 点击"取消选择"：清除所有选中状态

### 地址管理交互 (AF-06)

**数据加载 (D-08)：**
1. 用户切换到"自动填充"页面
2. 调用 `GET /api/address/get?containerId={id}` 获取当前容器的地址
3. 有数据：显示查看模式
4. 无数据：显示空状态

**编辑地址 (D-08)：**
1. 用户点击"编辑"按钮
2. 切换到编辑模式，输入框填充现有数据
3. 用户修改后点击"保存"
4. 验证：姓名和手机号非空，手机号 11 位数字
5. 调用 `POST /api/address/save`，切换回查看模式

**删除地址：**
1. 用户点击"删除"按钮
2. 弹出确认对话框
3. 确认后调用 `POST /api/address/delete`，显示空状态

### 地址表单检测交互 (AF-07)

**检测流程 (D-09, D-10, D-11, D-12)：**
1. 页面加载完成后（`did-finish-load`），webview preload 脚本执行地址表单检测
2. 扫描页面中的 input/textarea 元素，匹配特征：
   - 姓名字段：`name` 属性含 `name`/`realname`/`username`，或 `placeholder` 含"姓名"/"收件人"
   - 手机号字段：`type="tel"`，或 `name` 属性含 `phone`/`mobile`/`tel`
   - 地址字段：`name` 属性含 `address`/`addr`，或 `placeholder` 含"地址"/"详细地址"
3. 三个字段中匹配到 2 个即触发地址保存横幅（D-10）
4. 复用 Phase 32 表单检测框架（D-11）

**地址自动填充：**
1. 页面加载完成后，主进程查询当前容器的地址数据
2. 如果有地址且未被"永不保存"，通过 IPC 发送到 webview preload
3. preload 脚本查找地址表单字段，填入姓名、手机号、地址
4. 每次导航/刷新都触发（D-12）

### 容器切换联动

切换容器时：
1. 重新加载凭据列表（过滤当前容器的凭据）
2. 重新加载地址数据（当前容器的地址）
3. 清空搜索框
4. 收起所有展开的详情行

- **HTTP API 模式：** `src/settings-page.js` 中的 fetch API 调用模式

### 与现有功能的边界

- **凭据存储：** 复用 Phase 32 的 credential-manager.js，设置页只做展示和删除
- **地址存储：** 独立的 SQLite 表，与凭据表分离
- **表单检测：** 复用 Phase 32 的 webview-preload.js 检测框架，地址检测扩展此框架
- **Cookie 管理：** 凭据/地址存储独立于 Cookie，使用独立的 SQLite 表 + safeStorage 加密
- **下载面板：** 地址保存横幅 z-index (9997) 与 credential-save-banner 一致，低于下载面板 (9998)

- 密码在设置页默认遮罩显示（`••••••••`），用户主动点击"显示"才切换明文
- 地址数据使用 safeStorage 加密存储（与凭据一致）
- 批量删除需二次确认，防误操作
