## 地址表单字段

### 字段定义

| Option | Description | Selected |
|--------|-------------|----------|
| 基础三字段 | 姓名、手机号、详细地址（省市区+街道+门牌号） | ✓ |
| 完整地址拆分 | 姓名、手机号、省、市、区、街道、门牌号、邮编 | |
| 含公司信息 | 姓名、手机号、公司、详细地址 | |

**User's choice:** 基础三字段（推荐）
**Notes:** 用户认为基础三字段足够日常使用，避免过度复杂

### 存储策略

| Option | Description | Selected |
|--------|-------------|----------|
| 单地址 | 每个容器只能保存一个地址（简单，覆盖写入） | ✓ |
| 多地址 | 每个容器可保存多个地址，填充时选择 | |
| 全局共享 | 地址全局共享，不按容器隔离 | |

**User's choice:** 单地址（推荐）
**Notes:** 用户认为单地址足够，简化实现和使用

### 保存方式

| Option | Description | Selected |
|--------|-------------|----------|
| 弹出提示 | 保存时弹出提示横幅（类似凭据保存），用户确认后保存 | ✓ |
| 手动输入 | 用户在设置页手动输入地址信息 | |
| 自动保存 | 检测到地址表单提交时自动保存，无需确认 | |

**User's choice:** 弹出提示（推荐）
**Notes:** 用户认可与凭据保存一致的交互模式

### 管理功能

| Option | Description | Selected |
|--------|-------------|----------|
| 查看+编辑 | 用户在设置页可以查看和编辑已保存的地址 | ✓ |
| 查看+删除 | 用户只能查看和删除，不能编辑 | |
| 仅通过表单更新 | 地址只能通过重新提交表单更新 | |

**User's choice:** 查看+编辑（推荐）
**Notes:** 用户认为编辑功能有必要，避免重新提交表单

## 地址表单检测

### 检测策略

| Option | Description | Selected |
|--------|-------------|----------|
| 多字段特征匹配 | 检测姓名、手机号、地址等字段特征，匹配到 2+ 个即认为是地址表单 | ✓ |
| 表单属性匹配 | 检测 form[action] 或特定 class/id 关键词（如 address、shipping） | |
| 双重验证 | 结合字段特征和表单属性双重验证 | |

**User's choice:** 多字段特征匹配（推荐）
**Notes:** 用户认可字段特征匹配，更通用且不依赖特定属性

### 匹配阈值

| Option | Description | Selected |
|--------|-------------|----------|
| 2/3 匹配 | 姓名、手机号、详细地址三个字段中匹配到 2 个即触发 | ✓ |
| 3/3 全匹配 | 必须三个字段全部匹配才触发 | |
| 1/3 即触发 | 只要检测到地址相关字段就触发 | |

**User's choice:** 2/3 匹配（推荐）
**Notes:** 用户认为 2/3 阈值平衡了准确性和覆盖度

### 检测关系

| Option | Description | Selected |
|--------|-------------|----------|
| 统一检测 | 地址表单和登录表单使用相同检测逻辑，统一处理 | ✓ |
| 独立检测 | 地址表单和登录表单使用独立检测逻辑，互不干扰 | |
| 优先级检测 | 先检测登录表单，如果不是再检测地址表单 | |

**User's choice:** 统一检测（推荐）
**Notes:** 用户认可统一检测框架，减少代码重复

### 检测时机

| Option | Description | Selected |
|--------|-------------|----------|
| 单次检测 | 只在页面加载完成后检测一次 | ✓ |
| 持续监听 | 使用 MutationObserver 持续监听 DOM 变化 | |
| 加载+聚焦双检测 | 页面加载检测 + 表单聚焦时再次检测 | |

**User's choice:** 单次检测（推荐）
**Notes:** 用户认为单次检测足够，避免性能开销
