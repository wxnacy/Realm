  <files>src/webview-preload.js, src/renderer.js</files>
  <action>
    根因（已确认，勿重查）：outside-click 监听挂在宿主 document（renderer.js:3785-3791），网页跑在 &lt;webview&gt; guest 进程（renderer.js:761），guest 点击不冒泡到宿主 document，监听器永远收不到网页区域点击。

    选定机制：guest preload 捕获阶段监听 + sendToHost 转发（不选 window blur——无法区分 devtools/切窗等焦点变化，误关风险高）。现有 webview-preload.js 已有同款 sendToHost 桥接范式（media:detected），完全复用：

    (1) src/webview-preload.js — 在文件末尾（contextBridge.exposeInMainWorld 块之后）追加：用 `window.addEventListener('mousedown', ..., true)`（捕获阶段，页面 stopPropagation 也拦不住；isolated world 的 preload 可正常收 DOM 事件），回调里 `ipcRenderer.sendToHost('media:outside-click')`。加 JSDoc 注释说明用途（转发 guest 点击给 renderer 用于关闭浮动媒体面板，per D-03）。注意：preload 是 sandbox 环境，只用 electron 的 ipcRenderer（顶部已 require），禁止引入任何 Node 全局/路径模块（无 __dirname）。

    (2) src/renderer.js — webview 的 ipc-message 监听器（925-936，现有 `if (e.channel === 'media:detected')` 分支）追加 `else if (e.channel === 'media:outside-click')` 分支：面板开着才关——`if (state.mediaPanelOpen) toggleMediaPanel();`（toggleMediaPanel 自带状态翻转+active class 联动，勿重复操作 DOM）。

    保留宿主 document 的既有 outside-click 监听（3785-3791）——它仍负责工具栏/标签栏等宿主 chrome 区域的点击关闭，两者互补。false-close 天然免疫：面板浮层在宿主 DOM（z-index 9998），点面板自身命中宿主元素不触达 guest；只有点网页区域才进 guest。

    不改动 createWebviewForTab 的 preload 属性接线（776 行已挂载 webview-preload.js）。遵循 AGENTS.md 代码风格。
