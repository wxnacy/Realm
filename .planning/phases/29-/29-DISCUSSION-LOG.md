## 功能开关粒度

### Q1: 多媒体功能的开关粒度？

| Option | Description | Selected |
|--------|-------------|----------|
| 单一总开关（推荐） | 一个总开关控制所有多媒体功能（嗅探 + 面板 + 播放器）。关闭时全部停止，开启时全部恢复。最简洁。 | ✓ |
| 两个开关 | 探测开关 + 播放器开关 分开控制。用户可能只想关闭嗅探但保留播放器。 | |
| 三个独立开关 | 探测 / 面板 / 播放器 各自独立开关。最大灵活性，但设置项过多。 | |

**User's choice:** 单一总开关
**Notes:** 符合 Success Criteria 的"播放器功能开关"措辞

---

### Q2: 开关是全局设置还是按容器独立？

| Option | Description | Selected |
|--------|-------------|----------|
| 全局设置（推荐） | 所有容器共享一个全局开关，设置一次全部容器生效。简单直观。 | ✓ |
| 按容器独立设置 | 每个容器独立开关。不同容器可以有不同的多媒体策略。 | |

**User's choice:** 全局设置
**Notes:** 多媒体功能具有全局性质，按容器独立设置增加不必要的复杂度

---

### Q3: 开关状态存储在哪里？

| Option | Description | Selected |
|--------|-------------|----------|
| electron-store settings（推荐） | 存储在 electron-store 的 settings 中（如 settings.mediaPlayer.enabled），与其他设置项一致。 | ✓ |
| 独立配置文件 | 存储在独立配置文件中。增加维护成本。 | |

**User's choice:** electron-store settings
**Notes:** 保持与其他设置项的存储一致性

---

### Q4: 切换开关后是否即时生效，还是需要重启应用？

| Option | Description | Selected |
|--------|-------------|----------|
| 即时生效（推荐） | 切换开关后立即生效：关闭时立即停止嗅探、清空列表、隐藏按钮；开启时立即恢复。 | ✓ |
| 重启生效 | 切换后需要重启应用才生效。实现更简单但用户体验差。 | |

**User's choice:** 即时生效
**Notes:** 用户体验优先

---

## 域名白名单交互

### Q1: 域名白名单的 UI 交互模式？

| Option | Description | Selected |
|--------|-------------|----------|
| 标签式（推荐） | 输入框 + 回车添加 + 标签式显示。每个域名一个标签，点击 × 删除。紧凑直观。 | ✓ |
| 列表式 | 表格列表式，每行一个域名 + 删除按钮。信息密度高但占用空间大。 | |
| 文本区域 | 文本区域，每行一个域名。最简单但缺乏视觉反馈和输入验证。 | |

**User's choice:** 标签式
**Notes:** 参考 Chrome 扩展的权限管理标签式设计

---

### Q2: 域名白名单的过滤逻辑？

| Option | Description | Selected |
|--------|-------------|----------|
| 白名单过滤模式（推荐） | 默认"全部"（所有域名嗅探）。白名单非空时，仅嗅探白名单中的域名。 | ✓ |
| 黑名单排除模式 | 默认"全部"。白名单为黑名单，列出的域名不进行嗅探。 | |

**User's choice:** 白名单过滤模式
**Notes:** 符合 Success Criteria 的"默认为全部"措辞

---

### Q3: 域名白名单是否自动包含子域名？

| Option | Description | Selected |
|--------|-------------|----------|
| 包含子域名（推荐） | 白名单包含 example.com 时，自动匹配 www.example.com、api.example.com 等子域名。 | ✓ |
| 精确匹配 | example.com 不匹配 www.example.com。需要手动添加每个子域名。 | |
| 两种模式可选 | 用户可选择精确匹配或子域名匹配。最灵活。 | |

**User's choice:** 包含子域名
**Notes:** 更实用，减少用户配置负担

---

### Q4: 白名单为空时的 UI 展示？

| Option | Description | Selected |
|--------|-------------|----------|
| 显示提示+输入框（推荐） | 白名单为空时显示提示文字"所有域名都进行探测"，并显示一个"添加域名"的输入框。 | ✓ |
| 显示"全部"标签 | 白名单为空时显示"全部"标签（不可删除），表示当前为全域名模式。 | |

**User's choice:** 显示提示+输入框
**Notes:** 更直观地引导用户操作

## 关闭时的资源释放

### Q1: 功能关闭时，webRequest.onResponseStarted 监听器如何处理？

| Option | Description | Selected |
|--------|-------------|----------|
| 回调内检查开关（推荐） | 在 webRequest 回调中检查开关状态，关闭时直接 return 不处理。无需移除/重建监听器。 | ✓ |
| 动态移除/注册监听器 | 关闭时移除 onResponseStarted 监听器，开启时重新注册。更彻底但需要管理引用。 | |

**User's choice:** 回调内检查开关
**Notes:** 实现最简单，避免监听器管理的复杂性

---

### Q2: 功能关闭时，媒体检测脚本注入如何处理？

| Option | Description | Selected |
|--------|-------------|----------|
| 注入前检查开关（推荐） | 在 renderer.js 注入脚本前检查开关状态，关闭时跳过注入。加一个 if 判断即可。 | ✓ |
| 脚本内部检查 | 注入脚本内部检查开关状态。脚本仍然注入但不执行检测逻辑。 | |

**User's choice:** 注入前检查开关
**Notes:** 更彻底，避免不必要的脚本注入

---

### Q3: 功能关闭时，已打开的播放器窗口如何处理？

| Option | Description | Selected |
|--------|-------------|----------|
| 不关闭已打开窗口（推荐） | 功能关闭时，已打开的播放器窗口继续播放直到用户关闭。不强制关闭正在播放的窗口。 | ✓ |
| 自动关闭所有播放器窗口 | 功能关闭时，自动关闭所有已打开的播放器窗口。更彻底但可能中断用户。 | |

**User's choice:** 不关闭已打开窗口
**Notes:** 避免丢失播放进度，用户体验更好

---

### Q4: 功能关闭时，已检测到的媒体列表如何处理？

| Option | Description | Selected |
|--------|-------------|----------|
| 清空所有列表（推荐） | 功能关闭时，清空所有容器的媒体列表，隐藏媒体面板和按钮。下次开启时重新检测。 | ✓ |
| 保留列表但隐藏UI | 功能关闭时，保留已检测的媒体列表但隐藏 UI。下次开启时显示之前的列表。 | |

**User's choice:** 清空所有列表
**Notes:** 保持状态一致性，避免显示过期数据

---

## 关闭时的页面行为

### Q1: Success Criteria 提到"页面恢复正常行为：视频文件正常下载、文本正常展示"。具体指什么？

| Option | Description | Selected |
|--------|-------------|----------|
| 恢复浏览器原生行为（推荐） | 功能关闭时，m3u8/mp4 等视频 URL 不再被嗅探器拦截，浏览器原生行为恢复。 | ✓ |
| 静默嗅探不显示 | 功能关闭时，视频 URL 仍然被嗅探但不显示 UI。 | |

**User's choice:** 恢复浏览器原生行为
**Notes:** 符合 Success Criteria 的明确要求

---

### Q2: 功能关闭时，用户在页面中点击视频链接的行为？

| Option | Description | Selected |
|--------|-------------|----------|
| 链接点击恢复正常（推荐） | 功能关闭时，webview 的点击链接行为恢复正常：点击 m3u8/mp4 链接时触发浏览器原生行为。 | ✓ |
| 链接行为不变 | 功能关闭时，链接点击行为不变（仍然在新标签打开），只是不嗅探。 | |

**User's choice:** 链接点击恢复正常
**Notes:** 完全恢复浏览器原生行为

---

### Q3: Success Criteria 提到"文本正常展示"——具体指 m3u8 文件内容在页面中显示为文本？

| Option | Description | Selected |
|--------|-------------|----------|
| m3u8 内容正常显示为文本（推荐） | 功能关闭时，m3u8 文件内容（HLS 播放列表文本）在页面中正常显示为文本。 | ✓ |
| m3u8 触发下载 | 功能关闭时，m3u8 文件触发下载而不是显示文本。 | |

**User's choice:** m3u8 内容正常显示为文本
**Notes:** 与 Chrome 浏览器行为一致

---

### Q4: 功能关闭时，mp4/webm 文件在 webview 中的行为？

| Option | Description | Selected |
|--------|-------------|----------|
| 原生播放（推荐） | 功能关闭时，mp4/webm 文件在 webview 中原生播放（Chromium 内置支持），不触发下载。 | ✓ |
| 触发下载 | 功能关闭时，mp4/webm 文件触发下载。 | |

**User's choice:** 原生播放
**Notes:** 用户补充：mp4 正常模式也想 Chrome 一样可以播放。与 Chrome 浏览器行为一致。
