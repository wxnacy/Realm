**第一步：创建 container-manager.js（per D-01）**

从 main.js 提取容器管理逻辑到独立模块。模块导出函数，不互相 require（per D-02）。

文件结构：
```
container-manager.js
├── DEFAULT_CONTAINERS 常量（4 个默认容器）
├── configStore（electron-store 实例，name: 'realm-config'）
├── containers Map
├── initContainers() — 从 configStore 加载容器，为每个容器创建 session.fromPartition('persist:container-{id}')
├── getContainers() — 返回容器配置数组（id, name, color, icon），不含 session 对象
├── getContainer(id) — 返回单个容器或 undefined
├── createContainer({ name, color, icon }) — 生成 ID（使用 crypto.randomUUID 短 UUID 避免碰撞 per RESEARCH.md Pitfall 1）、创建 Session、持久化、返回容器配置
├── updateContainer(id, { name, color, icon }) — 更新容器配置、持久化、返回更新后的容器
├── deleteContainer(id) — 拒绝 id='default'、清理 session.clearStorageData()、从 Map 和 configStore 中移除（per D-13）
└── module.exports
```

容器 ID 生成策略（per RESEARCH.md Pitfall 1）：
- 基础 ID：name 转小写，非字母数字字符替换为连字符，合并连字符，去除首尾连字符
- 唯一性检查：如果 containers Map 已有此 ID，追加 crypto.randomUUID().slice(0, 8) 后缀
- 支持中文字符（正则：/[^a-z0-9一-龥]/g）

createContainer 必须验证 name 非空（per D-11），抛出错误时包含中文错误消息。

**第二步：创建 ipc-handlers.js（per D-01, D-03）**

集中注册所有 IPC 处理器。使用新的通道命名格式（per D-03）。

IPC 通道列表：
- container:list → containerManager.getContainers()
- container:create → containerManager.createContainer({ name, color, icon })
- container:update → containerManager.updateContainer(id, { name, color, icon })
- container:delete → containerManager.deleteContainer(id)
- container:current → windowManager.getCurrentContainer(windowId)
- container:switch → windowManager.switchContainer(windowId, containerId, container)

每个处理器对入参做类型校验（per RESEARCH.md Security Domain V5）。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer → IPC → Main | 渲染进程通过 IPC 发送容器操作请求，主进程必须验证所有入参 |
| innerHTML 风险 | 容器名称可能包含恶意脚本，渲染时必须使用 textContent 或转义 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | ipc-handlers.js | medium | mitigate | 所有 IPC 处理器对入参做类型和格式校验（name 为非空字符串，color 为 hex 格式） |
| T-01-02 | Tampering | renderer.js | medium | mitigate | 容器名称渲染使用 textContent 而非 innerHTML，防止 XSS |
| T-01-03 | Tampering | container-manager.js | medium | mitigate | 容器 ID 使用白名单字符（a-z, 0-9, 中文, 连字符），碰撞时追加 UUID 后缀 |
| T-01-SC | Tampering | npm installs | low | accept | Phase 1 不引入新依赖，仅使用已有的 electron 和 electron-store |
</threat_model>
