    3. 只读清单的实现：用一条共用的旗标容忍片段字符串 `FLAG_TOLERANCE = '(?:\\s+-\\S+(?:\\s+(?!-)\\S+)?)*'`（与 `PACKAGE_MANAGER_INSTALL_PATTERNS` 现用片段同形），为每个工具预编译出一组正则 `readOnlyRes`（**按下面的顺序拼装，次序与守卫缺一不可**）：

          **⚠ 硬约束：`verbs` 为空时（`npx` / `bunx` / `uvx`）必须 `if (verbs.length > 0)` 跳过构造，绝不拼出空捕获组。** `…\\s+\\b()\\b` 的空捕获组匹配空串，实测 `npx foo` / `npx create-app` / `npx skills add -g -y` 全部命中 → 该工具**一切**形态都判只读 → `matchInstall` 返回 `null` → 配合 `matchesWhitelist('npx foo', ['npx']) === true` 落到 `allow` **零卡片**（正好把既有 P1-b-1 与阶段目标打穿）。空 `readOnlyRes` 条目数组本身的语义就是「该工具没有只读形态」→ `.some()` 恒 `false` → 默认拒绝，这才是正确行为。
       2. **守卫式**：对每条 `guarded` 预编译 `new RegExp(g.pattern)`（`g.pattern` 由 `tool` + `FLAG_TOLERANCE` 拼成，见下）。
       3. **复合式**（本计划只有 `uv`）：`new RegExp('\\buv\\b' + FLAG_TOLERANCE + '\\s+pip\\s+\\b(' + subVerbs.join('|') + ')\\b')`。
       4. **裸形式**（`bareIsInstall === false` 时才生成）：`new RegExp('\\b' + tool + '\\b' + FLAG_TOLERANCE + '\\s*$')` —— 该式同时覆盖裸命令名（`npm`）与**纯旗标**形态（`npm --version` / `uv --version` / `brew -v`），这正是既有「裸命令名不命中」断言依赖的通道。

       - `audit`：`\\bnpm\\b` + `FLAG_TOLERANCE` + `\\s+\\baudit\\b(?!\\s+(?:-\\S*)?fix\\b)`（`pnpm` 同形）—— 负向先行断言拒掉紧跟的 `fix` / `--fix` ⇒ `npm audit` / `npm audit --json` / `npm audit --production` / `pnpm audit` 命中（只读），`npm audit fix` / `npm audit fix --force` / `npm audit --fix` / `pnpm audit --fix` 不命中（→ 默认拒绝）。
       **为什么用正则而不是手写分词**：旗标与其取值不可区分（`pnpm --filter a run build` vs `npm -g i pkg`），只有正则回溯能同时正确处理这两种形态（既有断言分别要求 `null` 与 install）。**但该片段同时带来一个结构性代价**：取值槽可以吞掉真正的子命令（把 `npm -g install list` 读成「旗标 `-g` 取值 `install`，子命令 `list`」）—— 因此第 4 步的**纵深优先**是必需的，不是可选的优化。**不要**改成 token 级分词（跳过 KEY=VALUE 与旗标取首个 token）：`pnpm --filter a run build` 会被读成子命令 `a` → 判 install，直接打破既有锁定负例（见 must_haves.prohibitions）。
