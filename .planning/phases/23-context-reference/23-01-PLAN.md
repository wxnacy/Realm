   - 运行 `npx electron-rebuild` 确保原生模块为 Electron 编译（Pitfall 2 from RESEARCH）
   - 验证 nodejieba 可加载: `node -e "require('nodejieba')"`

2. 在 favorites-manager.js 顶部添加 nodejieba 延迟加载:
   ```javascript
   // nodejieba 延迟加载：原生模块必须在 app.whenReady 之后加载

   ```

3. 在 favorites-manager.js 中新增 `segmentForFts5(text)` 辅助函数:
   - 使用 nodejieba.cut(text) 分词
   - 用空格连接分词结果（FTS5 unicode61 tokenizer 按空格分隔 token）
   - nodejieba 未加载时回退到原文（不预分词）

4. 在 favorites-manager.js 中新增 `ensureFts5Index()` 函数（per D-11 启动时全量构建）:
   - 检查 favorites_fts 虚拟表是否存在（通过 sqlite_master 查询）
   - 不存在时创建: `CREATE VIRTUAL TABLE favorites_fts USING fts5(content, tokenize='unicode61')`
   - 全量构建索引: 遍历 favorites 表所有记录，对每条的 title + url 进行 nodejieba 预分词后 INSERT 到 favorites_fts
   - 创建触发器 favorites_ai（INSERT）、favorites_ad（DELETE）、favorites_au（UPDATE）自动维护索引
   - 触发器中的 content 也需要预分词: `segmentForFts5(new.title || ' ' || new.url)`
   - 在 `ensureTable()` 函数末尾调用 `ensureFts5Index()`

5. 在 favorites-manager.js 中新增 `searchFulltext({ keyword, limit = 50 })` 函数（per D-12 默认50条）:
   - 对 keyword 调用 segmentForFts5 预分词
   - 查询（per D-10 索引标题+URL，FTS5 仅索引 title 和 url 字段）: `SELECT f.* FROM favorites_fts fts JOIN favorites f ON fts.rowid = f.id WHERE fts.content MATCH ? ORDER BY rank LIMIT ?`
   - 返回与 searchRecords 相同形状的结果数组
   - 错误处理: nodejieba 未加载时回退到现有 LIKE 模式搜索

6. 在 favorites-manager.js 的 module.exports 中导出 searchFulltext 函数
