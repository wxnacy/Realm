## 溢出处理策略

### 问题 1：当收藏栏内容超出可用宽度时，如何处理溢出？

| Option | Description | Selected |
|--------|-------------|----------|
| 下拉菜单（推荐） | 点击 >> 按钮后弹出下拉菜单，显示所有溢出的收藏项和文件夹，类似 Chrome 的行为 | ✓ |
| 横向滚动 | 收藏栏内容可以横向滚动，鼠标滚轮支持横向滚动 | |
| 截断隐藏 | 收藏栏固定高度，超出部分直接截断不显示 | |

**User's choice:** 下拉菜单（推荐）
**Notes:** 与 Chrome 行为一致，用户熟悉

### 问题 2：溢出菜单（>> 按钮点击后）如何展示内容？

| Option | Description | Selected |
|--------|-------------|----------|
| 单层菜单 + 子菜单 | 溢出菜单只显示顶级溢出项，文件夹点击后展开子菜单 | ✓ |
| 树状结构（推荐） | 溢出菜单显示完整的树状结构，用缩进表示层级 | |
| 仅收藏项 | 溢出菜单只显示收藏项，文件夹不显示在溢出菜单中 | |

**User's choice:** 单层菜单 + 子菜单
**Notes:** Chrome 风格，级联子菜单

### 问题 3：收藏栏空白区域的右键菜单是否包含「隐藏收藏栏」选项？

| Option | Description | Selected |
|--------|-------------|----------|
| 是，右键可隐藏（推荐） | 收藏栏整体右键菜单中添加「隐藏收藏栏」选项，与 BAR-04 需求一致 | ✓ |
| 否，仅设置页控制 | 仅在设置页面中控制显示/隐藏 | |

**User's choice:** 是，右键可隐藏（推荐）
**Notes:** 与 BAR-04 需求一致

### 问题 4：>> 溢出按钮的位置？

| Option | Description | Selected |
|--------|-------------|----------|
| 固定右侧（推荐） | >> 按钮固定在收藏栏最右侧，不随内容滚动 | ✓ |
| 跟随内容末尾 | >> 按钮在收藏栏内容末尾，可能需要滚动才能看到 | |

**User's choice:** 固定右侧（推荐）
**Notes:** 与 Chrome 行为一致

## 文件夹展开交互

### 问题 1：收藏栏中点击文件夹时的交互方式？

| Option | Description | Selected |
|--------|-------------|----------|
| 下拉菜单（推荐） | 与 Chrome 一致：点击文件夹弹出下拉菜单，子文件夹悬停向右展开，交互熟悉 | ✓ |
| 内联展开 | 文件夹点击后在收藏栏下方展开内联区域，显示子内容 | |
| 导航到收藏夹页面 | 文件夹点击后导航到收藏夹页面的对应文件夹 | |

**User's choice:** 下拉菜单（推荐）
**Notes:** Chrome 风格

### 问题 2：文件夹子菜单是否支持悬停自动展开？

| Option | Description | Selected |
|--------|-------------|----------|
| 悬停自动展开（推荐） | 鼠标悬停在文件夹上约 300ms 后自动展开子菜单，与 Chrome 一致 | ✓ |
| 仅点击展开 | 必须点击才能展开，悬停不触发 | |

**User's choice:** 悬停自动展开（推荐）
**Notes:** 与 Chrome 行为一致

### 问题 3：文件夹下拉菜单的宽度如何确定？

| Option | Description | Selected |
|--------|-------------|----------|
| 自适应宽度（推荐） | 文件夹下拉菜单宽度根据内容自适应，最大宽度限制（如 300px） | ✓ |
| 固定宽度 | 固定宽度（如 250px），超出部分截断显示省略号 | |

**User's choice:** 自适应宽度（推荐）
**Notes:** 最大宽度 300px

### 问题 4：嵌套文件夹的子菜单展开方向？

| Option | Description | Selected |
|--------|-------------|----------|
| 右侧弹出（推荐） | 子菜单从文件夹右侧弹出，与父菜单并排显示 | ✓ |
| 内部替换 | 子菜单在父菜单内部替换显示，返回时回到父菜单 | |

**User's choice:** 右侧弹出（推荐）
**Notes:** Chrome 风格

## 视觉样式与间距

### 问题 1：收藏栏在窗口中的位置？

| Option | Description | Selected |
|--------|-------------|----------|
| 地址栏下方（推荐） | 收藏栏位于地址栏下方、标签栏上方，与 Chrome 布局一致 | ✓ |
| 标签栏下方 | 收藏栏位于标签栏下方、网页内容上方 | |

**User's choice:** 地址栏下方（推荐）
**Notes:** 与 Chrome 布局一致

### 问题 2：收藏栏的高度？

| Option | Description | Selected |
|--------|-------------|----------|
| 与地址栏等高（推荐） | 与地址栏高度一致（约 32px），保持视觉统一 | ✓ |
| 略矮（28px） | 略低于地址栏（约 28px），更紧凑 | |
| 自适应高度 | 自定义高度，根据内容自适应 | |

**User's choice:** 与地址栏等高（推荐）
**Notes:** 约 32px

### 问题 3：收藏项 favicon 加载失败时的降级显示？

| Option | Description | Selected |
|--------|-------------|----------|
| 使用当前软件的icon | favicon 加载失败时使用 Realm 应用图标作为降级显示 | ✓ |
| 默认地球图标（推荐） | favicon 加载失败时显示默认地球图标，与 Chrome 行为一致 | |
| 首字母图标 | favicon 加载失败时显示收藏项标题的首字母 | |
| 不显示图标 | favicon 加载失败时不显示图标，只显示标题 | |

**User's choice:** 使用当前软件的icon
**Notes:** 用户自定义选择

### 问题 4：收藏栏与地址栏之间的分隔方式？

| Option | Description | Selected |
|--------|-------------|----------|
| 分隔线（推荐） | 收藏栏与地址栏之间有 1px 分隔线，与标签栏风格统一 | ✓ |
| 无分隔线 | 收藏栏与地址栏之间无分隔线，背景色区分 | |

**User's choice:** 分隔线（推荐）
**Notes:** 与标签栏风格统一

## 右键菜单集成

### 问题 1：收藏栏右键菜单是否复用现有的 Electron Menu API 模式？

| Option | Description | Selected |
|--------|-------------|----------|
| 复用现有模式（推荐） | 复用 Phase 13/15 的 Electron Menu API 模式，保持代码一致性 | ✓ |
| 独立实现 | 收藏栏右键菜单独立实现，不依赖现有菜单系统 | |

**User's choice:** 复用现有模式（推荐）
**Notes:** 保持代码一致性

### 问题 2：收藏栏中收藏项的右键菜单包含哪些选项？

| Option | Description | Selected |
|--------|-------------|----------|
| 标准三项（推荐） | 收藏项右键菜单包含：在新标签页打开、编辑、删除，与 Chrome 一致 | ✓ |
| 扩展菜单 | 收藏项右键菜单包含更多选项：在新标签页打开、在新窗口打开、编辑、删除、复制链接 | |

**User's choice:** 标准三项（推荐）
**Notes:** 与 Chrome 一致

### 问题 3：收藏栏中文件夹的右键菜单包含哪些选项？

| Option | Description | Selected |
|--------|-------------|----------|
| 标准五项（推荐） | 文件夹右键菜单包含：在新标签页中打开所有书签、重命名、删除、添加书签、添加文件夹 | ✓ |
| 简化三项 | 文件夹右键菜单简化为：重命名、删除、添加书签 | |

**User's choice:** 标准五项（推荐）
**Notes:** 与 Chrome 一致

### 问题 4：收藏栏菜单项的操作如何调用后端？

| Option | Description | Selected |
|--------|-------------|----------|
| 直接调用现有 API（推荐） | 菜单项直接调用现有 API（如 favoritesManager.updateFavorite），不引入新的 IPC 通道 | ✓ |
| 新建专用 IPC | 为收藏栏菜单创建专用的 IPC 通道 | |

**User's choice:** 直接调用现有 API（推荐）
**Notes:** 不引入新的 IPC 通道
