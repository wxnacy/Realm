**1. 创建 `src/bookmarks-bar.js`（新文件）**

实现收藏栏渲染和基础交互模块，采用 IIFE 或模块模式（与现有 favorites-page.js 风格一致）：

**数据加载与渲染：**
- `async function loadBookmarksBar()`：调用 `window.realmAPI.bookmarksBar.listFavorites(0)` 获取根目录收藏项，调用 `window.realmAPI.bookmarksBar.getFolderTree()` 获取文件夹树（仅取根级文件夹），然后调用 `renderBookmarksBar(favorites, rootFolders)`
- `function renderBookmarksBar(favorites, folders)`：清空 `#bookmarksBarList`，先渲染文件夹再渲染收藏项（Chrome 顺序），每个项创建 DOM 元素并绑定事件
- `function createBookmarkItem(record)`：创建收藏项 DOM，包含 favicon img（onerror 降级到 icon.png per D-09）和标题 span。点击时导航到 URL，Cmd/Ctrl+Click 时在新标签页打开
- `function createFolderItem(folder)`：创建文件夹 DOM，包含文件夹 SVG 图标和标题。点击和悬停交互在 Plan 02 实现，本 task 仅创建占位 DOM 并标记 `data-folder-id`

**溢出计算：**
- `function calculateOverflow()`：获取 `#bookmarksBarList` 的 `clientWidth`，遍历子元素累加 `offsetWidth`，超出可用宽度（容器宽度 - 溢出按钮宽度 32px - 内边距）的项设置 `display: none`，同时收集溢出项数据到 `overflowItems` 数组。如果 `overflowItems.length > 0`，为 `#bookmarksOverflowBtn` 添加 `.visible` 类，否则移除
- 使用 `ResizeObserver` 监听 `#bookmarksBarList` 尺寸变化时重新计算（per 18-RESEARCH.md Pitfall 1 避免方案：确保 DOM 布局完成后计算）
- 监听窗口 `resize` 事件时也触发重新计算

**点击导航：**
- 收藏项点击事件处理：检查 `event.metaKey || event.ctrlKey`，如果是则调用 `window.open(url, '_blank')`，否则在当前活动标签页的 webview 中导航（通过 `window.realmAPI.navigateTab(url)` 或等效的标签页导航 API）
- 所有收藏项和文件夹元素添加 `title` 属性显示完整标题（浏览器原生 tooltip）

**暴露全局函数供 renderer.js 调用：**
```javascript
window.bookmarksBar = {
  load: loadBookmarksBar,
  recalculate: calculateOverflow,
};
```
