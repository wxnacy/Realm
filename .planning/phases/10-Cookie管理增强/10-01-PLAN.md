  <action>
1. 在 cookie-manager.js 中新增 4 个函数（per D-05, D-15）：
   - getSessionCookies(containerId)：调用 session.fromPartition(`persist:container-${containerId}`).cookies.get({}) 返回 Session Cookie 列表
   - getFileCookies(containerId)：读取 `{userData}/cookies/{containerId}/cookies.json` 文件，解析并返回 Cookie 数组
   - editCookie(containerId, cookieData)：调用 session.cookies.set() 更新 Cookie，然后调用 saveCookies(containerId) 同步文件
   - deleteSingleCookie(containerId, cookieData)：调用 session.cookies.remove(url, name) 删除 Cookie，然后调用 saveCookies(containerId) 同步文件

2. 在 ipc-handlers.js 中新增 4 个 IPC 通道（per D-05, D-15）：
   - cookie:get-session → getSessionCookies(containerId)
   - cookie:get-file → getFileCookies(containerId)
   - cookie:edit → editCookie(containerId, cookieData)
   - cookie:delete-single → deleteSingleCookie(containerId, cookieData)
   所有通道使用 ipcMain.handle() 模式，与现有 get-containers 等通道一致

3. 在 src/preload.js 中新增 4 个 API 方法（per D-05, D-15）：
   - getSessionCookies(containerId) → ipcRenderer.invoke('cookie:get-session', containerId)
   - getFileCookies(containerId) → ipcRenderer.invoke('cookie:get-file', containerId)
   - editCookie(containerId, cookieData) → ipcRenderer.invoke('cookie:edit', containerId, cookieData)
   - deleteSingleCookie(containerId, cookieData) → ipcRenderer.invoke('cookie:delete-single', containerId, cookieData)
   挂载到 window.realmAPI 下，与现有方法（如 getContainers, switchContainer）风格一致

4. 编辑 Cookie 时的注意事项：
   - name 字段设为只读（灰色显示），避免技术复杂性（修改 name 实际是创建新 Cookie 并删除旧 Cookie）
   - domain、path、secure、httpOnly、sameSite 等字段可编辑
   - expirationDate 使用 Unix 时间戳（秒），与 Electron Session API 一致
   - 编辑后必须同时更新 Session 和文件，避免重启后丢失修改

5. 删除 Cookie 时的注意事项：
   - 必须同时从 Session 和文件中移除，避免重启后重新出现
   - 使用 session.cookies.remove(url, name) 按 name 精确删除
   - url 需要根据 domain 和 secure 属性动态构建

6. 获取 File Cookie 时的注意事项：
   - 读取 `{userData}/cookies/{containerId}/cookies.json` 文件
   - 文件不存在时返回空数组，不报错
   - JSON 解析失败时返回空数组，并 console.error 记录错误

7. 实现完成后，运行冒烟测试验证 API 调用链。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer → Main Process (IPC) | 渲染进程通过 IPC 调用主进程 Cookie 操作 |
| Cookie Data → DOM | Cookie 数据插入 DOM 时必须使用 textContent，禁止 innerHTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-01 | Tampering | Cookie 编辑 | high | mitigate | 编辑后同步更新 Session 和文件，避免数据不一致 |
| T-10-02 | Information Disclosure | Cookie 删除 | medium | mitigate | 删除后同步从 Session 和文件中移除，避免残留 |
| T-10-03 | Elevation of Privilege | IPC 通道 | high | mitigate | 所有 IPC 通道使用 ipcMain.handle()，不暴露危险操作 |
| T-10-04 | Denial of Service | File Cookie 读取 | low | accept | 文件不存在时返回空数组，JSON 解析失败时返回空数组 |
| T-10-05 | Spoofing | Cookie 数据 | medium | mitigate | Cookie 数据使用 textContent 插入 DOM，禁止 innerHTML |
| T-10-06 | Repudiation | Cookie 操作 | low | accept | 不记录操作日志，用户可自行查看 Session 和文件状态 |
| T-10-SC | Tampering | npm/pip/cargo installs | high | mitigate | 本阶段不安装任何外部包，无供应链风险 |
</threat_model>
