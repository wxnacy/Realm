<objective>
闭合 Phase 49 的 Gap 1：**写侧允许落盘的任何技能都必然能被加载管线收进技能集**（ROADMAP 判据 1「新技能集在下一条消息即对模型可见」的完整性半边）。

三条独立成因，同归一类后果（工具报成功、磁盘有文件、技能永不加载）：

1. **CR-02** —— description 被字符串插值直接拼进 YAML frontmatter，含 `": "` / `#` / 裸标量形态时解析失败或静默截断；
2. **CR-03** —— description 在净化**之前**校验、净化后不复验，纯零宽字符可被净化为空串；
3. **WR-01** —— 写侧只按 `content` 计字节，加载期按整个 `SKILL.md`（含 frontmatter）计字节，边界带内（实测 ~1.06 KB）产出幽灵技能。

外加一条使失实原因可见的查找侧缺陷：`getSkillPromptIncluded` 用 `false` 同时表达「命中但超预算」与「根本不在技能集里」，导致工具向模型追加一句「技能段预算已满，仍可用 /skill:{name} 手动调用」—— 预算并未满，`/skill:{name}` 也解析不到。

Purpose: 把「写侧即加载侧」做成**可失败被观察**的代码事实。本计划的三条修法都落在既有文件的既有函数内（无范围蔓延），且都不新立拒绝码（九码闭合白名单不增不减）。

Output: `ai-skills-manager.js` 的 YAML 标量编码、净化后复验、组装全文字节闸、`getSkillPromptIncluded` 三态；`tests/test-manage-skill.js` 的 description 值域行与写↔读闸口边界行；`docs/product/ai-skills.md` §11.3 / §11.5 的口径纠正。
