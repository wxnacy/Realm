# Phase 04 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none（原生 CSS 变量系统） |
| Preset | not applicable |
| Component library | none |
| Icon library | 内联 SVG（stroke 风格，24x24 viewBox） |
| Font | -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, sans-serif |

**设计系统说明：** 项目使用原生 CSS 变量定义深色主题，无 shadcn/Tailwind。所有新增组件必须遵循现有 CSS 变量体系（`--bg-*`, `--text-*`, `--accent-*`, `--border-color`），不得引入外部设计系统。

## Spacing Scale

已确认使用 4px 基准的间距系统（与现有代码一致）：

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | 图标间距、内联元素间隙（`.action-btn` gap） |
| sm | 8px | 紧凑元素间距（`.toolbar` gap、`.tab-list` gap） |
| md | 16px | 默认元素间距（`.form-group` margin、`.container-list` padding） |
| lg | 24px | 区域内边距（`.modal-content` padding） |
| xl | 32px | 布局间隙 |
| 2xl | 48px | 主要区域分隔 |
| 3xl | 64px | 页面级间距 |

**例外：**
- Tab 最小宽度 120px（`--tab-min-width`），最大 240px（`--tab-max-width`）— 功能性尺寸，非间距
- 规则列表项内边距 12px — 介于 sm 和 md 之间，用于紧凑列表

## Component Inventory — Phase 04 新增/修改

### 1. Toggle Switch（新增）

**用途：** 规则启用/禁用切换

**结构：**
```
.toggle-switch
  .toggle-track
    .toggle-thumb
```

**样式规范：**
- Track: 36px 宽, 20px 高, 圆角 10px
- Track 关闭态: `--bg-tertiary` (#3a3a3a)
- Track 开启态: `--accent-color` (#3B82F6)
- Thumb: 16px 圆形, 白色 (#ffffff)
- Thumb 位置: 关闭时 left 2px, 开启时 left 18px
- 过渡动画: 0.2s ease

**交互规范：**
- 点击整个 track 区域切换状态
- 键盘：Enter/Space 切换
- 状态变化立即生效，通过 IPC 通知主进程

---

### 2. Draggable Rule Item（修改现有 `.rule-item`）

**用途：** 规则列表项，支持拖拽排序

**新增属性：**
- `draggable="true"` — 启用 HTML5 拖放
- `cursor: grab` — 默认光标
- `cursor: grabbing` — 拖拽中光标

**拖拽视觉反馈：**
- 拖拽中：被拖拽项透明度 0.5
- 放置目标：上方或下方显示 2px 高的 `--accent-color` 指示线
- 拖拽手柄：在规则项左侧添加 `⋮⋮` 图标（6px 宽, 24px 高, `--text-muted` 颜色）

**放置后行为：**
- 规则列表重新排序
- 新顺序通过 IPC 同步到主进程
- 持久化到 electron-store

---

### 3. Import/Export 按钮组（修改 `.rules-toolbar`）

**用途：** 规则导入/导出操作

**结构：**
```
.rules-toolbar
  .rule-form (现有)
  .rules-actions (新增)
    button.btn.btn-secondary#importRulesBtn — 导入规则
    button.btn.btn-secondary#exportRulesBtn — 导出规则
```

**布局：**
- `.rules-actions` 使用 flex 布局, gap 8px
- 位于 `.rule-form` 下方, margin-top 12px
- 按钮使用 `.btn-secondary` 样式（与现有按钮一致）

**导入行为：**
- 点击后触发隐藏的 `<input type="file" accept=".json">`
- 文件选择后解析 JSON，验证格式
- 成功：Toast 提示导入数量，刷新列表
- 失败：Toast 错误提示

**导出行为：**
- 点击后生成 JSON 文件并下载
- 文件名：`realm-rules-{timestamp}.json`
- 成功：Toast 提示导出数量

---

### 4. Shortcut Capture Box（已有 `.key-capture-box`，确认规范）

**用途：** 快捷键捕获输入框

**样式确认（与现有 CSS 一致）：**
- 高度 48px, flex 居中
- 背景 `--bg-tertiary`, 虚线边框 `--border-color`
- 捕获中：边框变为 `--accent-color`, 文字变为 `--text-secondary`
- 字体：monospace, 16px

**交互规范：**
- 打开捕获对话框后自动聚焦
- 按下任意键组合显示在框中（格式：`⌘+Shift+T`）
- Esc 取消捕获
- Enter 确认保存（如果已捕获有效组合）
- 不允许捕获单个修饰键（Ctrl、Shift、Alt、Meta 单独按下时忽略）

## Interaction Patterns

### 规则启用/禁用 Toggle

1. 用户点击规则项右侧的 toggle 开关
2. toggle 动画切换（0.2s ease）
3. 通过 IPC 发送 `rule:update` 请求，传递 `{ ruleId, enabled: !current }`
4. 主进程更新规则状态并持久化
5. 规则匹配逻辑自动跳过禁用的规则

### 规则拖拽排序

1. 用户按住拖拽手柄（`⋮⋮` 图标）开始拖拽
2. 被拖拽项透明度降低至 0.5
3. 拖拽过程中，鼠标悬停的规则项上方或下方显示放置指示线
4. 释放后，规则列表重新排序
5. 通过 IPC 发送 `rule:reorder` 请求，传递新的规则 ID 顺序
6. 主进程更新规则顺序并持久化

### 规则导入

1. 用户点击"导入规则"按钮
2. 系统打开文件选择对话框（filter: `.json`）
3. 用户选择文件后，渲染进程读取文件内容
4. 验证 JSON 格式：必须包含 `rules` 数组，每项包含 `containerId` 和 `pattern`
5. 验证通过：合并到现有规则（不覆盖），Toast 成功提示
6. 验证失败：Toast 错误提示，不修改现有规则

### 规则导出

1. 用户点击"导出规则"按钮
2. 渲染进程收集当前所有规则
3. 生成 JSON 文件（格式：`{ rules: [...], exportedAt: timestamp }`）
4. 触发浏览器下载，文件名带时间戳
5. Toast 成功提示

### 快捷键捕获

1. 用户点击快捷键项的"修改"按钮
2. 打开快捷键捕获对话框，`key-capture-box` 自动聚焦
3. 用户按下键盘组合（如 `⌘+Shift+T`）
4. 组合键实时显示在捕获框中
5. 用户点击"保存"或按 Enter 确认
6. 通过 IPC 发送 `shortcut:update` 请求
7. 主进程验证快捷键未被占用，更新并持久化
8. 对话框关闭，快捷键列表刷新
