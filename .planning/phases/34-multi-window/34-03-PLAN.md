将 main.js 中所有 `windowManager.getMainWindow()` 后跟 `.webContents.send(...)` 的调用替换为 `windowManager.broadcast(...)`（per D-10）。

具体替换规则：
- 模式 A（带条件检查）：`const mainWindow = windowManager.getMainWindow(); if (mainWindow && !mainWindow.isDestroyed()) { mainWindow.webContents.send('channel', ...args); }` → `windowManager.broadcast('channel', ...args);`
- 模式 B（直接调用）：`const win = windowManager.getMainWindow(); win.webContents.send('channel', ...args);` → `windowManager.broadcast('channel', ...args);`

需要逐一审查 main.js 中所有 getMainWindow() 调用点（约 10 处），区分两种语义：
1. **需要广播到所有窗口**（替换为 broadcast）：show-quit-hint、bookmarks-bar:refresh、container-switched 等通知类
2. **需要特定窗口引用**（保留 getMainWindow）：DevTools 操作、播放器相关、需要窗口实例做参数的场景

已知需要替换的调用点（基于 PATTERNS.md 分析）：
- `_notifyBookmarksBarRefresh()`（line 583）：`mainWindow.webContents.send('bookmarks-bar:refresh')` → `windowManager.broadcast('bookmarks-bar:refresh')`
- before-quit 的 show-quit-hint（已在 Task 1 处理）
- 其他 `mainWindow.webContents.send(...)` 调用点需要逐一判断

已知需要保留 getMainWindow 的调用点：
- 播器窗口相关的 getMainWindow 调用（D-13）
- DevTools 操作（需要窗口实例引用）
- requestActionConfirmation 中的 getMainWindow（需要发送到特定窗口）

注意：不要盲目替换所有 getMainWindow() 调用。只替换那些语义为"通知所有窗口"的调用。需要窗口实例引用的调用保留不变。

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dock 菜单 → 主进程 | Dock 菜单 click 直接在主进程执行，无 IPC 跨进程 |
| Application Menu → 主进程 | Menu Accelerator 在主进程处理，触发 shortcut:triggered IPC 到焦点窗口 |
| 焦点窗口 → shortcut:triggered | 快捷键派发到焦点窗口的 webContents，焦点窗口必须在 managedWindowIds 中 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-34-01 | Elevation of Privilege | assertTrustedSender managedWindowIds | critical | mitigate | 已在 Plan 02 实现，本 Plan 依赖 Plan 02 的 assertTrustedSender 泛化 |
| T-34-06 | Tampering | Dock 菜单窗口创建 | medium | accept | Dock 菜单仅在 macOS 原生 Dock 右击时可用，非用户主动操作无法触发 |

</threat_model>
