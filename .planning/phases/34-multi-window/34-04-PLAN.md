Gap 2 修复 — 首次启动 Cmd+W 关闭窗口的初始化顺序问题。

**根因分析：**
main.js 第2510行 `createMainWindow()` 在第2519行 `shortcutManager.registerShortcuts()` 之前调用。`registerShortcuts()` 通过 `ensureAppListener()` 设置 `app.on('web-contents-created')` 监听器，该监听器只对之后创建的 webContents 生效。首次启动时主窗口的 webContents 在监听器设置之前创建，因此没有 `attachInputListener` 挂载，Electron 默认的 Cmd+W 关闭窗口行为被触发。

**修复方案：**
将 `shortcutManager.registerShortcuts()` 调用移到 `createMainWindow()` 之前。

具体操作：
1. 找到第2510行 `const mainWindow = windowManager.createMainWindow('default', defaultContainer);`
2. 找到第2519行 `shortcutManager.registerShortcuts();`
3. 将 `shortcutManager.registerShortcuts();` 这一行移到 `createMainWindow()` 调用之前

注意：第2608-2612行有类似的代码（可能是 activate 事件处理），也需要做同样的顺序调整——将 `shortcutManager.registerShortcuts()` 移到 `createMainWindow()` 之前。

调整后的顺序：
```javascript
// 先注册快捷键（设置 web-contents-created 监听器）
shortcutManager.registerShortcuts();
// 再创建主窗口（此时监听器已就绪，主窗口 webContents 会被自动挂载 attachInputListener）
const mainWindow = windowManager.createMainWindow('default', defaultContainer);
```
