创建独立的对话存储模块 ai-conversations-manager.js，复用 better-sqlite3 模式（参考 history-manager.js）。

数据库设计（per D-01, D-02）：
- 独立数据库文件：ai-conversations.db（与 history.db 分离）
- conversations 表：id TEXT PRIMARY KEY, title TEXT NOT NULL, model TEXT, provider TEXT, token_total INTEGER DEFAULT 0, created_at INTEGER NOT NULL, updated_at INTEGER NOT NULL
- messages 表：id TEXT PRIMARY KEY, conversation_id TEXT NOT NULL, role TEXT NOT NULL, content TEXT, tool_calls TEXT, tool_results TEXT, page_snapshots TEXT, created_at INTEGER NOT NULL, FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
- 索引：idx_messages_conversation ON messages(conversation_id, created_at), idx_conversations_updated ON conversations(updated_at DESC)

核心函数：
1. initDatabase() — 初始化数据库连接，WAL 模式
2. createConversation(options) — 创建新对话，返回对话对象
3. getConversations(limit=50) — 获取对话列表（按 updated_at 降序）
4. getConversation(id) — 获取单个对话详情
5. updateConversation(id, updates) — 更新对话元数据（标题、token 等）
6. deleteConversation(id) — 删除对话及其所有消息（CASCADE）
7. saveMessages(conversationId, messages) — 事务批量保存消息
8. getMessages(conversationId) — 获取对话的所有消息（按 created_at 升序）

消息保存时的序列化规则（per RESEARCH Pitfall 3）：
- tool_calls 和 tool_results 字段 JSON.stringify 序列化
- 单个工具结果超过 100KB 时截断为摘要 + truncated 标记
- page_snapshots 字段保存 @ 引用的页面快照（per D-15）

导出所有公共函数供 ai-manager.js 调用。

扩展 ai-manager.js 实现一对话一实例模式（per D-09）：

1. 新增属性：
   - this.conversationStore = require('./ai-conversations-manager')
   - this.currentConversationId = null
   - this.conversationMeta = {} // 当前对话元数据

2. 新增方法：
   - switchConversation(conversationId) — 切换对话的核心逻辑：
     a. 如果有旧对话，保存当前消息到数据库（per D-07）
     b. 调用 cleanupCurrentAgent() 销毁旧实例（abort + unsubscribe + nullify）
     c. 从数据库加载目标对话消息
     d. 创建新 Agent 实例（复用现有 init 逻辑）
     e. 通过 agent.state.messages = [...] 直接注入历史消息（per RESEARCH Pitfall 2，不触发 LLM）
     f. 设置 currentConversationId
   
   - saveCurrentConversation() — 保存当前对话：
     a. 获取 agent.state.messages
     b. 提取元数据（model, provider, token_total）
     c. 调用 conversationStore.saveMessages()
     d. 更新 conversation 元数据（updated_at, token_total）
   
   - createNewConversation() — 创建新对话：
     a. 调用 conversationStore.createConversation()
     b. 清理旧 Agent 实例
     c. 创建新 Agent 实例
     d. 设置 currentConversationId
   
   - deleteConversation(conversationId) — 删除对话：
     a. 如果是当前对话，先创建新对话
     b. 调用 conversationStore.deleteConversation()
   
   - renameConversation(conversationId, newTitle) — 重命名对话：
     a. 调用 conversationStore.updateConversation(id, { title: newTitle })
   
   - getConversations() — 获取对话列表：
     a. 返回 conversationStore.getConversations()

3. 修改 _setupEventBroadcasting()：
   - 在 agent_end 事件中调用 saveCurrentConversation()（per D-11）
   - 记录对话元数据：model, provider, token_total, duration（per D-12）

4. 修改 newConversation()：
   - 调用 createNewConversation() 替代现有的 agent.reset()

5. 在 init() 末尾调用 conversationStore.initDatabase()

新增 IPC 通道（ipc-handlers.js）：
- ai:get-conversations — 获取对话列表
- ai:create-conversation — 创建新对话
- ai:switch-conversation — 切换对话（传入 conversationId）
- ai:delete-conversation — 删除对话
- ai:rename-conversation — 重命名对话（传入 conversationId, newTitle）

暴露 conversationAPI（src/preload.js）：
```javascript
conversationAPI: {
  getConversations: () => ipcRenderer.invoke('ai:get-conversations'),
  createConversation: () => ipcRenderer.invoke('ai:create-conversation'),
  switchConversation: (id) => ipcRenderer.invoke('ai:switch-conversation', id),
  deleteConversation: (id) => ipcRenderer.invoke('ai:delete-conversation', id),
  renameConversation: (id, title) => ipcRenderer.invoke('ai:rename-conversation', id, title),
}
```

注意：恢复对话时使用当前全局模型配置（per D-13），不保存/恢复模型配置。
