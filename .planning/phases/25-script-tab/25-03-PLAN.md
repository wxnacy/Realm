1. **ai-manager.js**：新增 `executeScript(script, webContentsId, onStepUpdate)` 异步函数（放在 validateScriptForSteps 之后）。

   执行逻辑（per D-04/D-09/D-11/D-12）：
   - 参数：script（脚本对象）、webContentsId（活跃标签页 webContents ID）、onStepUpdate（步骤状态回调）
   - 遍历 script.steps，对每个 step：
     a. 调用 onStepUpdate({ index, status: 'executing', step })
     b. 对 step 执行 sanitizeInput 消毒
     c. 调用 cdpManager.executeAction(webContentsId, step.action, step.target, step.options)
     d. 如果返回 success=false，调用 onStepUpdate({ index, status: 'error', error: result.error })，返回 `{ success: false, stoppedAt: index, error: result.error }`
     e. 如果成功，调用 onStepUpdate({ index, status: 'success', result })
     f. 如果 step.action === 'navigate' 或 step.waitFor === 'load'，等待页面 load 事件（使用 cdpManager.executeCommand 的 Page.loadEventFired 或 setTimeout 5秒超时兜底）
   - 全部成功返回 `{ success: true, results }`
   - 捕获异常时返回 `{ success: false, stoppedAt: i, error: err.message }`

   注意：executeScript 不做用户确认（确认在 generate_script 工具返回前由 AI 处理，或在脚本预览卡片的"执行脚本"按钮处由用户确认）。

2. **main.js**：在现有 IPC 处理器区域（参考 action:confirm/action:cancel 的注册位置约第1692行附近）添加：

   - `ipcMain.handle('script:execute', async (event, script) => { ... })`：
     a. 校验 script 对象格式
     b. 获取当前活跃标签页的 webContentsId（通过 require('./ipc-handlers').getActiveWebviewContentsId()）
     c. 调用 executeScript(script, webContentsId, (update) => { event.sender.send('script:step-update', update) })
     d. 返回执行结果

   - `ipcMain.handle('script:stop', (event) => { ... })`：
     a. 设置全局标志位中断执行循环
     b. 返回 { stopped: true }

   在 executeScript 外部维护一个 `let scriptAbortController = null;` 变量用于支持中断。script:execute 开始时创建新的 AbortController，script:stop 调用 abort()。executeScript 的步骤循环中检查 abortSignal.aborted。

1. **src/preload.js**：在现有 realmAPI 对象中（参考 actionConfirm/actionCancel 的位置）添加：

   - `scriptExecute: (script) => ipcRenderer.invoke('script:execute', script)`
   - `scriptStop: () => ipcRenderer.invoke('script:stop')`
   - `onScriptStepUpdate: (callback) => ipcRenderer.on('script:step-update', (event, data) => callback(data))`

   注意：onScriptStepUpdate 使用 ipcRenderer.on 而非 invoke，因为它是来自主进程的推送消息。

2. **src/renderer.js**：在 renderScriptPreviewCard 函数中完善执行相关逻辑：

   - 绑定"执行脚本"按钮点击事件：
     a. 禁用执行按钮，显示"执行中..."状态
     b. 调用 `window.realmAPI.scriptExecute(script)` 启动执行
     c. 注册 `window.realmAPI.onScriptStepUpdate(handleStepUpdate)` 监听步骤更新

   - 新增 `handleStepUpdate(update)` 函数：
     a. 根据 update.index 找到对应的 .script-step-item 元素
     b. 更新步骤状态类名（step-executing/step-success/step-error）
     c. 如果 status === 'error'，在步骤下方显示错误信息和操作按钮（重试/跳过/终止）
     d. 如果 status === 'success'，更新序号为绿色对勾
     e. 如果 status === 'executing'，显示加载动画（复用现有 spinner 模式）

   - 重试/跳过/终止按钮逻辑：
     - 重试：重新执行当前步骤
     - 跳过：标记当前步骤为 step-skipped，继续执行下一步
     - 终止：调用 `window.realmAPI.scriptStop()` 停止执行

   - 执行完成后：
     a. 恢复执行按钮文本为"重新执行"
     b. 启用执行按钮
     c. 显示执行结果摘要（成功/失败/已跳过步骤数）

   - 渲染进程初始化时（在 setupEventListeners 或初始化区域）：
     注册 `window.realmAPI.onScriptStepUpdate` 监听器
