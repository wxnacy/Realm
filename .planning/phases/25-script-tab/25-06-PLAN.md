<objective>
修复 UAT gap G-25-23：AI「整理标签页」只输出 markdown 文本建议，标签页实际不会被重排。

根因（已诊断，勿重复排查）：suggest_tab_groups 的 semantic/mixed 策略不返回 {groups} 结构（ai-manager.js:2307-2362），渲染端仅在 resultData.groups 存在时渲染卡片（src/renderer.js:3935），默认策略恰是 semantic 导致卡片永不渲染；且 AI 无结构化回传通道，系统提示词也未告知卡片存在。

修复方向（用户已锁定，必须遵循）：新增 apply_tab_groups 工具 —— AI 完成语义分组后调用该工具提交结构化 groups，工具校验 + 规范化后以 {groups} 结构返回，渲染端复用现有 renderTabGroupCard 渲染可交互卡片，用户点「应用分组」走现有 tab:reorder IPC 完成重排。

Purpose: 打通「AI 语义分组 → 结构化回传 → 卡片确认 → 实际重排」的完整链路。
Output: apply_tab_groups AI 工具、同步更新的系统提示词与策略 message、渲染端卡片渲染扩展
</objective>

1. **在 _buildRealmTools() 中注册 apply_tab_groups 工具**（紧跟 suggest_tab_groups 之后，ai-manager.js:2364 附近）：

   - 工具元信息：name 为 apply_tab_groups，label 为「应用标签分组」，description 说明用途——提交语义分组后的结构化分组结果，分组将以卡片形式展示给用户确认，用户点击「应用分组」后标签页才会实际重排。
   - parameters：type object，properties.groups 为数组，每项为对象 { name: string（组名，必填）, tabs: array（标签页对象数组，每项至少含 id: string） }，groups 必填。
   - execute(toolCallId, params) 逻辑（严格按此顺序）：
     a. 调用 sanitizeInput(params) 消毒入参（与既有工具一致的模式）。
     b. 基础校验：groups 必须是非空数组，每项必须有非空 name 和 tabs 数组；不合法时返回错误 message（content text JSON 含 error 字段），提示 AI 按 { groups: [{ name, tabs: [{ id }] }] } 格式重试。
     c. 调用 tabManager.getTabs() 获取权威标签列表，构建有效 tab id 集合和 id → tab 数据映射。
     d. 遍历每组每个 tab 条目：id 不在有效集合中的条目丢弃并记录到 droppedTabIds（防止 AI 幻觉 id 直接驱动重排）；有效条目以 tabManager 权威数据重建 { id, title, url, containerId, faviconUrl, pinned }（不信 AI 提交的元数据，字段缺省值与 suggest_tab_groups 的 tabData 标准化一致：title 缺省 '(无标题)'，url/faviconUrl 缺省空串，pinned 布尔化）。
     e. 丢弃清洗后为空的分组（记录 droppedGroups）。
     f. 全部无效时返回 content text JSON { groups: [], message: 说明所有提交的 tab id 均无效、要求 AI 先调用 get_tabs 核对 }；不得抛出异常中断对话。
     g. 成功时返回 content text JSON { groups: 规范化后的分组, message: '分组已提交，将以卡片形式展示给用户确认，用户点击「应用分组」后标签页才会实际重排。请告知用户分组已就绪，等待用户确认。' }，details 含 { totalTabs, groupCount, droppedTabIds, droppedGroups }。

   - 遵循项目既有模式：JSDoc 注释块说明工具用途/策略/防幻觉校验语义；单引号、2 空格缩进；返回结构为 { content: [{ type: 'text', text: JSON.stringify(...) }], details }（与 suggest_tab_groups 一致）。

2. **更新 suggest_tab_groups 的 semantic 策略返回 message**（ai-manager.js:2313 附近）：在原有分组指引后追加明确指令——完成语义分组后必须调用 apply_tab_groups 工具提交结构化结果（groups 数组，每组 { name, tabs: [{ id }] }，id 取自上面 tabs 数据），提交后会渲染卡片给用户确认，未经 apply_tab_groups 提交的分组不会生效。

   - 使用指南中「整理标签页」条目（~443 行）更新为：使用 suggest_tab_groups 分析标签页（默认 semantic 策略；用户要求按域名分组时用 domain）；若返回的是待分组标签数据而非分组结果，完成分组后必须调用 apply_tab_groups 提交结构化分组，分组卡片会展示给用户确认。
