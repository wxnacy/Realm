在 ai-manager.js 的 `_buildRealmTools()` 方法中，紧接在 `execute_action` 工具定义之后添加 `generate_script` 工具。

工具结构遵循现有模式（参考 get_tabs/execute_action 的 name/label/description/parameters/execute 签名）。

1. **工具定义**：name 为 'generate_script'，label 为 '生成脚本'，description 描述为"根据自然语言描述生成可执行的自动化脚本"。parameters 包含：
   - description (string, required): 用户的任务描述
   - containerId (string, optional): 目标容器 ID，默认使用当前活跃容器

2. **execute 函数**：遵循签名 `async (toolCallId, params) => {...}`

   执行逻辑：
   - 获取当前活跃容器 ID（通过 resolveToolTargetTab 或 getContainersLazy）
   - AI 根据 params.description 生成脚本 JSON 结构（脚本格式 per D-01/D-02/D-03）
   - 脚本 JSON 结构：`{ name: string, description: string, steps: Array<{action, target, options?, waitFor?}>, containerId: string }`
   - 对生成的脚本调用 validateScriptForSteps(script) 进行静态分析
   - 如果不安全，返回包含 safe=false 和 reason 的结果
   - 如果安全，返回脚本 JSON

   **关键**：generate_script 工具的 execute 函数内部，AI 会基于 description 生成步骤序列。这个工具的 execute 函数需要：
   - 构造一个脚本对象
   - 调用新增的 validateScriptForSteps() 验证
   - 返回 `{ content: [{ type: 'text', text: JSON.stringify(script) }], details: { scriptName: script.name, stepCount: script.steps.length, safe: true } }`

   注意：generate_script 的"生成"逻辑由 AI 模型自身完成（工具返回格式供前端渲染），execute 函数负责格式校验和安全验证。

3. **action 枚举白名单**：定义常量 `SCRIPT_ALLOWED_ACTIONS` 数组，包含 ['navigate', 'click', 'type', 'scroll', 'wait', 'select', 'check', 'uncheck', 'focus', 'blur', 'submit', 'keydown', 'keyup']。此白名单独立于 execute_action 的 action enum（execute_action 有 screenshot/upload 等额外操作，脚本中不允许这些高风险操作）。

在 ai-manager.js 中新增 `validateScriptForSteps(script)` 函数，放在现有 `validateScript` 函数之后（约第177行附近）。

1. **函数签名**：`function validateScriptForSteps(script)`，参数为脚本对象（非字符串）

2. **验证逻辑**：
   - 校验 script.steps 存在且为数组
   - 遍历每个 step，验证 step.action 在 SCRIPT_ALLOWED_ACTIONS 白名单中
   - 如果 action 不在白名单中，返回 `{ safe: false, reason: '不允许的操作: ' + step.action }`
   - 对 step.target 和 step.options 中的所有字符串值执行危险模式检测（复用 validateScript 的 dangerousPatterns 列表）
   - 检测到危险模式时返回 `{ safe: false, reason: '步骤 ' + (i+1) + ' 包含危险调用: ' + name }`

3. **扩展危险模式列表**：在 validateScriptForSteps 中额外添加：
   - `\bfetch\s*\(` — 网络请求
   - `\bXMLHttpRequest\b` — XMLHttpRequest
   - `\.\.\/` — 路径遍历
   - `\bwindow\.\b` — window 对象访问（脚本步骤不应直接操作 window）
   - `\bdocument\.\b` — document 对象访问（脚本步骤通过 CDP 操作，不应内嵌 JS）

4. **返回格式**：`{ safe: boolean, reason?: string, details?: { stepIndex: number, pattern: string } }`

5. **在 generate_script 的 execute 函数中调用**：generate_script 工具的 execute 函数在构造完脚本对象后，调用 `const validation = validateScriptForSteps(script); if (!validation.safe) return { content: [...], details: { safe: false, reason: validation.reason } }`
