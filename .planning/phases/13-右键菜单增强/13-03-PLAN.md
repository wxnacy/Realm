  <action>
实现 favicon 完整数据流（仿照现有 page-title-updated → updateTabTitle 模式）：

**A. favicon 事件监听（src/renderer.js）**

在 createWebviewForTab（或等效 webview 事件绑定处，对照 753 行 page-title-updated 模式）添加：
```javascript
webview.addEventListener('page-favicon-updated', (e) => {
  const faviconUrl = e.favicons && e.favicons[0];
  if (!faviconUrl) return;
  tab.faviconUrl = faviconUrl;
  // 更新 DOM 中对应 img.src；若 img 不存在则跳过
  // 持久化：调用 window.realmAPI.updateTab(tab.id, { faviconUrl })（tab-manager.js 的 updateTab 是硬白名单，仅合并 url/title/lastActiveAt —— 必须同步完成 E 的白名单修改，否则 faviconUrl 被静默丢弃）
});
```

**B. Tab DOM 创建点统一加 favicon 元素（src/renderer.js）**

三处 Tab DOM 创建点（约 380-407 createTab、1090-1117 restoreTabs、1324-1351 renderTabs 重建分支）结构相同，均为 colorLine/title/closeBtn。在 title 前插入：
```javascript
const favicon = document.createElement('img');
favicon.className = 'tab-favicon';
favicon.src = tab.faviconUrl || '';
favicon.style.display = tab.faviconUrl ? '' : 'none'; // 无 favicon 时不占位
favicon.alt = '';
```
三处为复制粘贴代码，本次修改时抽取一个公共的 Tab DOM 创建辅助函数（如 createTabElement(tab)）统一三处调用，避免后续再出现三处漂移。

**C. 基础 .tab-favicon CSS（src/styles/main.css）**

在现有 .tab-pinned 规则（1119-1143）附近补充：
```css
.tab-favicon {
  width: 16px;
  height: 16px;
  flex-shrink: 0;
  vertical-align: middle;
}
.tab-pinned .tab-content {
  display: flex;
  align-items: center;
  justify-content: center;
}
```
确认现有 `.tab-pinned .tab-favicon` 规则（1128 附近）与新基础样式不冲突。

**D. 固定标签关闭按钮策略**

保持现状（固定 Tab 仍显示关闭按钮），但调整 CSS：`.tab-pinned .tab-close` 仅在 hover 时显示，避免 40px 宽度内与 favicon 重叠遮挡。若现有规则已是 hover 显示则无需改动。

**E. 持久化白名单修改（tab-manager.js，必做）**

tab-manager.js:151-165 的 `updateTab` 是硬白名单（仅合并 url/title/lastActiveAt），faviconUrl 必被静默丢弃。在该白名单中新增 `faviconUrl` 分支，使 `updateTab(tabId, { faviconUrl })` 能持久化。restoreTabs 恢复时 tab.faviconUrl 随持久化数据还原，DOM img.src 初始化（见 B）。IPC 接线（ipc-handlers.js:278）为透传，无需改动。

非目标：favicon 加载失败的回退图标（保持 display:none 即可，不引入默认图标资源）。
