在 download-manager.js 中新增三个函数，遵循现有代码风格（JSDoc 注释、console.error 错误处理、返回对象格式一致）：

1. **getAllDownloads(limit = 50, offset = 0)** — 全局查询所有容器的下载记录
   - SQL: `SELECT * FROM downloads ORDER BY start_time DESC LIMIT ? OFFSET ?`
   - 不按 container_id 过滤（per D-05 决策：面板显示所有容器记录）
   - db 未初始化时返回空数组

2. **deleteDownload(downloadId, deleteFile = false)** — 删除单条下载记录
   - 先查询记录获取 save_path
   - 如果 activeDownloads.has(downloadId)，先调用 cancelDownload(downloadId) 取消进行中的下载（per D-17）
   - deleteFile 为 true 且 save_path 非空且文件存在时，调用 fs.unlinkSync 删除本地文件
   - 文件删除失败不阻止记录删除（catch 后继续）
   - 删除 SQLite 记录: `DELETE FROM downloads WHERE id = ?`
   - 返回 `{ success: true }` 或 `{ success: false, error: '...' }`
   - save_path 安全验证：确认路径在用户下载目录内（防路径遍历，per RESEARCH.md Security Domain）

3. **clearAllDownloads()** — 清空所有下载历史
   - 只删除 SQLite 记录，不删除本地文件（per D-16 决策）
   - SQL: `DELETE FROM downloads`
   - 返回 `{ success: true, deletedCount: N }`

在 module.exports 中添加这三个新函数。

注释和文档使用中文。

**ipc-handlers.js 新增 3 个 IPC 通道：**

在现有 download:* 通道（约 L854-943）之后添加：

1. `download:list-all` — 调用 downloadManager.getAllDownloads(limit, offset)
   - 参数: (event, limit, offset)，默认 limit=50, offset=0
   - 返回: 下载记录数组

2. `download:delete-record` — 调用 downloadManager.deleteDownload(downloadId, deleteFile)
   - 参数: (event, downloadId, deleteFile)
   - 返回: { success, error? }

3. `download:clear-all` — 调用 downloadManager.clearAllDownloads()
   - 参数: (event)
   - 返回: { success, deletedCount }

遵循现有 download:* 通道的 try-catch 和 console.error 模式。
