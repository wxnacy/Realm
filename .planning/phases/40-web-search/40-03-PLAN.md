# Phase 40 Plan 03: 修复 all_failed 时搜索诊断信息展示

**目标**：当所有搜索 Provider 都失败时，web_search 工具展示 diagnostics.attempts 详情，而非返回通用消息。

## Gap

**G-40-6（major）**：doAutoSearch 返回 all_failed 时，web_search 的 `results.length===0` 分支返回通用消息「未找到搜索结果」，未展示 `diagnostics.attempts` 中的 Provider 名称、错误类型和错误消息。

**根因**：`doAutoSearch` 在全部 Provider 失败时返回 `{results:[], diagnostics:{status:'all_failed', attempts:[...]}}`（正常返回，非异常）。`ai-manager.js` 的 web_search execute 在 `results.length===0` 分支仅检查 results 为空，未检查 `diagnostics.status` 是否为 `all_failed`，因此走了通用的「未找到结果」路径。catch 块有完善的错误处理逻辑，但 all_failed 不触发 catch。

## Task 1: 修改 web_search results.length===0 分支

**文件**：`ai-manager.js`
**位置**：web_search 工具 execute 函数（第 2932-2940 行）
**修改**：在 `results.length===0` 分支中检查 `diagnostics.status==='all_failed'`，展示 attempts 详情

**read_first**：
- `ai-manager.js` 第 2920-2973 行（web_search 工具完整定义）
- `search-manager.js` 第 1354-1364 行（doAutoSearch all_failed 返回结构）
- `search-manager.js` 第 742-812 行（normalizeSearchResult / formatSearchResults 格式参考）

**action**：

在 `ai-manager.js` 第 2932 行的 `if (results.length === 0)` 分支中，添加对 `searchPayload.diagnostics` 的检查：

```javascript
if (results.length === 0) {
  // 检查是否为 all_failed 场景（所有 Provider 都失败）
  const diagnostics = searchPayload.diagnostics;
  if (diagnostics?.status === 'all_failed' && diagnostics.attempts?.length > 0) {
    const attemptsDetail = diagnostics.attempts.map((a, i) =>
      `  ${i + 1}. ${a.provider || '未知'}: ${a.error_type || 'error'} - ${a.message || '无详情'}`
    ).join('\n');
    return {
      content: [{
        type: 'text',
        text: `搜索「${query}」失败：所有 Provider 均不可用（共尝试 ${diagnostics.attempts.length} 个）。\n\n失败详情：\n${attemptsDetail}\n\n请检查网络连接或在设置中配置搜索 API Key。`,
      }],
      details: searchPayload,
    };
  }

  // 通用空结果消息（Provider 返回了0条结果，但不是全部失败）
  return {
    content: [{
      type: 'text',
      text: `未找到「${query}」的搜索结果。已尝试 Provider: ${provider}。请尝试换个关键词搜索。`,
    }],
    details: searchPayload,
  };
}
```

**acceptance_criteria**：
- `ai-manager.js` 第 2932 行附近存在 `diagnostics?.status === 'all_failed'` 检查
- all_failed 时返回的 text 包含每个 attempt 的 provider 名称、error_type 和 message
- all_failed 时返回的 text 包含「所有 Provider 均不可用」和「共尝试 N 个」字样
- 非 all_failed 的空结果仍返回原有的通用消息（不破坏现有行为）
- catch 块（第 2958-2971 行）保持不变（处理异常场景）

**verify**：
- `node -e` 测试：构造 `{results:[], diagnostics:{status:'all_failed', attempts:[{provider:'tavily',error_type:'auth',message:'401'},{provider:'brave',error_type:'rate_limited',message:'429'}]}}` 传入逻辑，输出包含「tavily: auth - 401」和「brave: rate_limited - 429」
- `node -e` 测试：构造 `{results:[], diagnostics:{}}` 传入逻辑，输出为通用「未找到」消息
