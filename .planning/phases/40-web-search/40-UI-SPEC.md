# Phase 40 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Phase UI Scope

**Phase 40 is a pure backend infrastructure phase.** No new UI components, pages, or visual elements are introduced.

Deliverables:
1. `search-manager.js` — 搜索 Provider 体系、速率限制器、SSRF 防护、Auto Fallback（全部主进程逻辑）
2. `web_search` AI 工具 — 注册到 `ai-manager.js` 的 `_buildRealmTools()`，输出为 markdown 文本

**Visual impact:** 搜索结果以 Markdown 编号列表渲染在现有 AI 聊天 UI 中（由 pi-agent-core SDK 的 Markdown 渲染管线处理）。不引入新的 DOM 元素、CSS 类或交互组件。

**Phase 41 的 UI 工作:** 设置页搜索配置子区域（Provider 选择下拉 + API Key 管理输入框 + 测试查询按钮）将在 Phase 41 的 UI-SPEC 中定义。

### web_search 工具输出格式

成功时返回 Markdown 编号列表：

```
1. [标题](url)
   摘要内容片段

2. [标题](url)
   摘要内容片段
```

失败时返回结构化错误（TOOL-04）：

```json
{
  "error": "所有搜索 Provider 均不可用",
  "attempts": [
    {"provider": "tavily", "status": "auth", "message": "API Key 无效或未配置"},
    {"provider": "anysearch_free", "status": "rate_limited", "message": "请求过于频繁"}
  ]
}
```

## UI Considerations

> Phase 40 引入的唯一视觉输出是 AI 聊天中的搜索结果文本。状态覆盖由现有 AI 聊天 UI 的 Markdown 渲染管线处理。

Applicable state considerations resolved: 0 new, 3 inherited from existing AI chat UI

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| {empty} | search results | ✅ covered | 当 web_search 返回空结果时，AI 收到空数组后会生成自然语言回复告知用户未找到结果（pi-agent-core SDK 行为） |
| {error} | search failure | ✅ covered | TOOL-04 定义了结构化错误返回（attempts 数组），AI 会将其转述为用户可理解的错误消息 |
| {loading} | search execution | ✅ covered | 搜索是同步的 AI 工具调用，用户看到的是 AI "正在思考" 的加载状态（现有 AI 聊天 UI 已有） |
