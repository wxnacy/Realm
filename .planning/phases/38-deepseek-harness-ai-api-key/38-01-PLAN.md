   - 对内置供应商: 从 _getCatalog() 获取提供商默认端点
   - 对自定义供应商: 使用 baseURL 参数
   - 调用 fetch(`${baseURL}/models`, { headers: { 'Authorization': `Bearer ${apiKey}` } })
   - 解析响应: data.data.map(m => ({ id: m.id, name: m.id }))
   - 错误处理: 网络错误返回 { error: '网络连接失败' }, HTTP 401 返回 { error: 'API Key 无效' }, 其他 HTTP 错误返回 { error: `HTTP ${status}` }
   - 返回: { models: Array<{id, name}> } 或 { error: string }

2. 扩展 getAvailableModels() 方法，返回值新增每个供应商的 envVarName 和 isBuiltin 字段

3. 在 main.js handleSettingsApi 中新增以下端点：
   - GET /api/ai/providers → 调用 aiManager.getAvailableModels()，返回供应商列表（含 envVarName、isBuiltin、customModels）
   - POST /api/ai/providers/:id/detect-models → 读取 body 中的 apiKey 和可选 baseURL，调用 aiManager.detectModels()，返回模型列表或错误
   - DELETE /api/ai/providers/:id → 从 reqUrl.pathname 解析 provider ID，调用新方法 aiManager.removeProvider(id)，返回 { success: true }
   - GET /api/ai/providers/:id/env-var → 调用 aiManager.detectEnvVar(id, reqUrl.searchParams.get('customName'))，返回检测结果

4. 在 AIManager 类中添加 removeProvider(providerId) 方法（per D-05）：
   - 从 configStore 删除 ai.providers.{providerId}
   - 如果 ai.activeProvider === providerId，删除 ai.activeProvider
   - 调用 init() 重新初始化

5. 扩展 _migrateLegacyConfig() 方法（per D-06）：
   - 迁移时保留 isBuiltin: true, envVarName: 'OPENAI_API_KEY'
   - 确保迁移后的数据结构与新格式一致
