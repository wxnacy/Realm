创建 favorites-manager.js，完全参考 history-manager.js 的架构模式。

模块结构：
1. 文件头 JSDoc 注释：说明模块用途、依赖、数据库路径
2. 延迟加载 better-sqlite3（与 history-manager.js 相同模式）
3. 数据库路径：复用 history.db（与 history-manager.js 共享同一数据库文件）
4. initDatabase() 函数：复用 history-manager.js 的 initDatabase，但需要共享同一 db 实例
   - 方案：从 history-manager.js 导出 db 实例，或在 favorites-manager.js 中也调用 initDatabase
   - 最佳方案：favorites-manager.js 接受外部传入的 db 实例（通过 setDatabase 函数），避免重复初始化
5. sanitizeContainerId() 函数：复制 history-manager.js 的实现（防 SQL 注入）
6. ensureTable() 函数：创建 favorites_{containerId} 表
   - 表结构：id INTEGER PRIMARY KEY AUTOINCREMENT, url TEXT NOT NULL, title TEXT NOT NULL DEFAULT '', favicon_url TEXT DEFAULT '', created_at INTEGER NOT NULL DEFAULT (strftime('%s', 'now') * 1000), UNIQUE(url)
   - 索引：idx_favorites_{id}_created_at (created_at DESC), idx_favorites_{id}_url (url)
7. CRUD 函数：
   - addRecord(containerId, { url, title, faviconUrl }) → { id } 或 { error: 'duplicate', message: '已收藏过该页面' }
     - INSERT OR IGNORE + 检查 lastInsertRowid 是否为 0（D-14 URL 去重）
   - updateRecord(containerId, id, { title }) → boolean
   - deleteRecord(containerId, id) → boolean
   - deleteRecords(containerId, ids) → number（批量删除）
   - listRecords(containerId, { offset, limit }) → Array（按 created_at DESC 排序，D-07）
   - searchRecords(containerId, { keyword, offset, limit }) → Array（匹配 title 和 url，D-09）
   - checkUrl(containerId, url) → { id, title, favicon_url } | null（检查 URL 是否已收藏）
   - getCount(containerId) → number
   - dropTable(containerId)（容器删除时调用）

导出：initDatabase, setDatabase, addRecord, updateRecord, deleteRecord, deleteRecords, listRecords, searchRecords, checkUrl, getCount, dropTable

注意：
- 没有 FIFO 淘汰（D-16 收藏数量不设上限）
- UNIQUE(url) 约束实现 URL 去重（D-14）
- 所有函数必须先调用 ensureTable 确保表存在
