<objective>
修复 11-UAT.md 报告的唯一 gap（severity: major，test 2）：规则导入失效。

**根因（已经 .planning/debug/rules-import-no-op.md 确诊，无需再查）**：

1. **主因——数据格式双重包裹**：src/settings-page.js handleFileSelect（约 558-582 行）把 JSON.parse 后的整个文件内容再次作为请求体 rules 字段的值 POST 到 /api/rules/import；而应用自身导出产物（assignment-rules.js:231-236 exportRules）本身就是 {rules:[...], exportedAt} 对象，服务端 main.js:647 解构出的 rules 是对象而非数组，被 assignment-rules.js:243-246 的 Array.isArray 校验拒绝，0 条导入。唯一能被接受的文件是裸 JSON 数组，而应用自身导出不产生该格式——导出→导入往返必然失败。
2. **次因——失败响应被静默吞掉**：服务端以 HTTP 200 返回失败对象，客户端不检查 result.success，反而弹出「已导入 undefined 条规则」的 2 秒 toast 并刷新出无变化的列表，用户感知为「没反应」。

Purpose: 使规则导出→导入往返真正可用，并让任何导入失败都以可读文案反馈给用户。
Output: 客户端解包归一化 + 失败响应检查；服务端归一化防御层；持久运行时回归冒烟测试。
</objective>
