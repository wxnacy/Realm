## cdp-manager.js — CDP 调试器管理器

新建 `cdp-manager.js` 模块，负责 webview 的 CDP 调试器生命周期管理。

**核心职责：**
1. 维护域名抓取列表（从 electron-store 读取）
2. webview 导航时检查 URL 域名是否匹配抓取列表（精确匹配 + 子域名匹配）
3. 匹配时附加 CDP 调试器（`webContents.debugger.attach('1.3')`），启用 Network 域
4. 非匹配时如果已附加则断开
5. 监听 CDP 网络事件，收集请求数据
6. 处理调试器断开事件（用户打开 DevTools 触发 detach），标记状态，不主动抢占
7. 调试器附加失败时通过 IPC 通知渲染进程显示 toast（D-04）

**模块接口：**
```javascript
// 导出
function init(store)  // 初始化，传入 electron-store 实例
function getDomains()  // 获取当前抓取域名列表
function addDomain(domain)  // 添加域名
function removeDomain(domain)  // 移除域名
function isEnabled()  // 是否开启开发者模式
function setEnabled(enabled)  // 设置开发者模式开关
function getRetentionDays()  // 获取保留天数
function setRetentionDays(days)  // 设置保留天数
function getQueueStats()  // 获取队列统计信息
function attachDebugger(webContents, containerId)  // 为 webview 附加调试器
function detachDebugger(webContents)  // 断开调试器
function handleNavigation(webContents, url, containerId)  // 导航时调用
function cleanup()  // 清理（应用退出时）
```

**域名匹配逻辑（per RESEARCH.md）：**
- 使用 `new URL(url).hostname` 解析
- 精确匹配：`hostname === domain`
- 子域名匹配：`hostname.endsWith('.' + domain)`
- 格式验证：域名不能为空，不能包含空格或特殊字符

**CDP 事件处理流程（per D-01/D-02/D-03）：**
1. `Network.requestWillBeSent`：记录 requestId、URL、method、timestamp、requestHeaders
2. `Network.responseReceived`：记录 statusCode、responseHeaders、contentType
3. `Network.dataReceived`：累积响应体数据块
4. `Network.loadingFinished`：调用 `Network.getResponseBody` 获取完整响应体，组装记录推入写入队列
5. `Network.loadingFailed`：记录错误信息

**响应体过滤（per D-08）：**
- 仅存储 Content-Type 为 `application/json`、`text/*`、`application/xml`、`application/javascript` 的响应体
- 二进制内容（图片、视频、文件下载）跳过存储，responseBody 置为空字符串
- 单条响应体大小限制 1MB，超过截断并标记 `[截断：原始大小 X bytes]`

**数据记录结构：**
```javascript
{
  requestId: string,       // CDP requestId
  url: string,             // 完整 URL
  method: string,          // GET/POST/PUT/DELETE 等
  statusCode: number,      // HTTP 状态码
  requestHeaders: object,  // 请求头
  requestBody: string,     // 请求体（POST/PUT）
  responseHeaders: object, // 响应头
  responseBody: string,    // 响应体（仅文本）
  contentType: string,     // Content-Type
  duration: number,        // 请求耗时（ms）
  containerId: string,     // 所属容器 ID
  createdAt: number,       // 时间戳
  size: number,            // 响应体大小（bytes）
}
```

**DevTools 冲突处理：**
- 监听 `debugger.on('detach')` 事件
- 标记该 webContents 的调试器为已断开状态
- 不主动重新附加（避免抢占用户 DevTools）
- 下次导航到匹配域名时自动重新附加

## dev-requests-writer.js — 写入队列模块

新建 `dev-requests-writer.js` 模块，负责异步批量写入 SQLite。

**核心职责：**
1. 维护内存写入队列
2. 每 2 秒定时 flush（per D-11）
3. 队列达到 1000 条时触发紧急 flush（per D-10）
4. 应用退出前 flush 所有待写入数据
5. 写入失败重试 3 次，超过后丢弃并记录 console.error（per D-12）
6. 使用 better-sqlite3 transaction 批量插入

**模块接口：**
```javascript
// 写入队列相关
function init(db)  // 初始化，传入 better-sqlite3 数据库实例
function enqueue(record)  // 将记录加入队列
function flush()  // 手动触发 flush
function getStats()  // 获取队列统计 { pending, lastFlush, totalWritten }
function cleanup()  // 清理定时器，执行最终 flush

// 查询函数（供 12-02 的 API 端点调用）
function queryRecords(containerId, options)  // 分页查询请求记录
function queryDomains(containerId)  // 获取已抓取的域名列表
function queryStats(containerId)  // 获取统计信息
function deleteRecord(containerId, id)  // 删除单条记录
function clearRecords(containerId)  // 清空容器的所有记录
```

**写入表名：** `dev_requests_${containerId}`（per D-06，每容器独立表）

**批量插入实现（per RESEARCH.md Code Examples）：**
```javascript
const insert = db.prepare(`INSERT INTO ${tableName} (...) VALUES (?, ?, ?, ...)`);
const insertMany = db.transaction((records) => {
  for (const record of records) {
    insert.run(...);
  }
});
```

**队列结构：**
- `queue: []` — 待写入记录数组
- `flushTimer: null` — 2 秒定时器
- `flushing: false` — 是否正在 flush
- `retryCount: Map()` — 每条记录的重试次数（最多 3 次）

**紧急 flush 逻辑：**
- enqueue 时检查 queue.length >= 1000
- 立即触发 flush，flush 期间新入队的记录正常接收
- flush 完成后继续定时 flush

**flush 期间的互斥：**
- 设置 `flushing = true`
- flush 期间 enqueue 仍可正常入队
- flush 完成后检查是否再次触发紧急 flush

## SQLite 表结构

在 `dev-requests-writer.js` 中添加 `initDatabase` 函数，在每个容器的 SQLite 数据库中创建 dev_requests 表。

**表结构（per D-05/D-06）：**
```sql
CREATE TABLE IF NOT EXISTS dev_requests_${containerId} (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  request_id TEXT NOT NULL,
  url TEXT NOT NULL,
  method TEXT NOT NULL,
  status_code INTEGER DEFAULT 0,
  request_headers TEXT DEFAULT '{}',
  request_body TEXT DEFAULT '',
  response_headers TEXT DEFAULT '{}',
  response_body TEXT DEFAULT '',
  content_type TEXT DEFAULT '',
  duration INTEGER DEFAULT 0,
  size INTEGER DEFAULT 0,
  container_id TEXT NOT NULL,
  created_at INTEGER NOT NULL DEFAULT (strftime('%s', 'now') * 1000)
);
CREATE INDEX IF NOT EXISTS idx_dev_requests_${containerId}_created_at
  ON dev_requests_${containerId} (created_at DESC);
CREATE INDEX IF NOT EXISTS idx_dev_requests_${containerId}_url
  ON dev_requests_${containerId} (url);
CREATE INDEX IF NOT EXISTS idx_dev_requests_${containerId}_method
  ON dev_requests_${containerId} (method);
```

复用 `history-manager.js` 的 `sanitizeContainerId` 验证模式，容器 ID 白名单 `[a-z0-9-]` 防 SQL 注入。

4. `POST /api/settings/remove-devdomain` — 移除抓取域名
   - 请求体：`{ domain: string }`
   - 更新 electron-store 和 cdpManager

5. `POST /api/settings/set-dev-retention` — 设置数据保留天数
   - 请求体：`{ days: number }`
   - 选项：3/7/14/30/0（0 = 永不删除）
   - 更新 electron-store

6. `GET /api/settings/devqueue-stats` — 获取写入队列统计
   - 返回 `{ pending: number, lastFlush: number, totalWritten: number }`

**electron-store 键名：**
- `devMode.enabled` — boolean，默认 false
- `devMode.domains` — string[]，默认 []
- `devMode.retentionDays` — number，默认 7
