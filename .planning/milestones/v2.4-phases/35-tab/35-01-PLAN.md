重构 tab-manager.js 支持多窗口 Tab 管理：

1. 修改 Tab 对象结构，新增 windowId 字段（per D-22）：
   - createTab(containerId, url, windowId) 第三个参数为 windowId
   - Tab 对象新增 windowId 字段，默认值为 null

2. 将 activeTabId 从单一字符串改为 Map<windowId, tabId>（per 研究 Open Questions #2）：
   - 新增 activeTabs = new Map()
   - getActiveTab(windowId) 按窗口获取活动 Tab
   - switchTab(tabId) 内部根据 tab.windowId 更新对应窗口的活动 Tab

3. 新增 getTabsByWindowId(windowId) 方法：
   - 返回指定窗口的所有 Tab 数组
   - 用于窗口关闭级联时获取需要销毁的 Tab 列表

4. 修改 closeTab(tabId) 逻辑：
   - 关闭 Tab 后，如果是该窗口最后一个 Tab，返回 { lastInWindow: true }
   - 渲染进程据此决定是否关闭窗口

5. 新增 closeTabsByWindowId(windowId) 方法：
   - 关闭指定窗口的所有 Tab
   - 返回关闭的 Tab ID 列表
   - 用于窗口关闭级联（D-16）

6. 修改 saveTabs() 持久化逻辑：
   - 保存时包含 windowId 字段
   - 恢复时处理旧数据（无 windowId 的 Tab 默认归属主窗口）

7. 修改 initTabs() 恢复逻辑：
   - 恢复 activeTabs Map（从持久化数据）
   - 兼容旧版单一 activeTabId 格式

8. 更新模块导出：
   - 导出 getTabsByWindowId, closeTabsByWindowId, getActiveTab(windowId)
   - 保留 getTabs(), getTab(tabId) 等现有接口兼容性

<task type="auto" tdd="true">
  <name>Task 2: 窗口关闭级联 + 活跃任务确认</name>
  <files>window-manager.js, main.js</files>
  <action>
实现窗口关闭级联机制和活跃任务确认对话框（per D-15, D-16, D-17）：

**window-manager.js 修改：**

1. 新增 closeWindowWithTabs(windowId) 方法：
   - 获取窗口内所有 Tab（调用 tabManager.getTabsByWindowId）
   - 逐个销毁 Tab 的 webContents（通过渲染进程通知或直接操作）
   - 调用 tabManager.closeTabsByWindowId(windowId) 清理主进程状态
   - 最后销毁窗口本身（win.destroy()）
   - 避免在 close 事件中调用 win.close() 导致递归（Pitfall 1）

2. 导出 closeWindowWithTabs

**main.js 修改：**

1. 新增窗口 close 事件处理器 setupWindowCloseHandler(win)：
   - 使用 closing 标志位防止重入（Pitfall 1）
   - e.preventDefault() 阻止默认关闭
   - 检测活跃任务（per D-17）：
     - downloadManager.getActiveDownloads() 获取活跃下载
     - 从渲染进程查询活跃媒体播放状态（需要 IPC 通道）
   - 无活跃任务：直接调用 closeWindowWithTabs(win.id)
   - 有活跃任务：弹出 dialog.showMessageBox 确认对话框（per D-15）
     - 按钮：['关闭', '取消']
     - defaultId: 1（取消是安全默认）
     - 显示任务列表（下载文件名 + 媒体类型）
     - 用户选择关闭：调用 closeWindowWithTabs(win.id)
     - 用户选择取消：closing = false，窗口保持打开

2. 在 createMainWindow 调用后注册 close 事件处理器

3. 新增 IPC 通道 window:check-active-tasks：
   - 渲染进程查询本窗口是否有活跃媒体播放
   - 返回 { hasActiveMedia: boolean, mediaList: [] }

4. 修改 window-all-closed 事件处理：
   - 保持现有逻辑：非 macOS 平台退出应用
   - macOS 平台：检查是否所有窗口都已销毁，是则退出

5. 确保 quitting 标志位与窗口关闭流程协调：
   - quitting = true 时跳过确认对话框，直接关闭
  </action>
  <verify>
    <automated>npm run dev</automated>
  </verify>
  <done>
    - 关闭窗口时，窗口内所有 Tab 的 webContents 被显式销毁
    - 无活跃任务时，窗口直接关闭（无确认对话框）
    - 有活跃下载时，弹出原生确认对话框
    - 用户选择"关闭"，窗口正常关闭
    - 用户选择"取消"，窗口保持打开
    - 关闭最后一个窗口时，应用退出（macOS 通过 Dock 退出）
    - 无递归调用 win.close() 的问题
  </done>
