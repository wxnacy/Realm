**模块结构：**

**数据库层（per D-09, D-10, D-11）：**

在 history.db 中创建 downloads 表（单表 + container_id 列，D-09 决策）：
```
CREATE TABLE IF NOT EXISTS downloads (
  id TEXT PRIMARY KEY,
  container_id TEXT NOT NULL,
  filename TEXT NOT NULL,
  url TEXT NOT NULL,
  save_path TEXT DEFAULT '',
  total_bytes INTEGER DEFAULT 0,
  received_bytes INTEGER DEFAULT 0,
  mime_type TEXT DEFAULT '',
  state TEXT NOT NULL DEFAULT 'progressing',
  start_time INTEGER NOT NULL,
  end_time INTEGER DEFAULT 0,
  can_resume INTEGER DEFAULT 0,
  source_url TEXT DEFAULT '',
  created_at INTEGER NOT NULL DEFAULT (strftime('%s', 'now') * 1000)
);
CREATE INDEX IF NOT EXISTS idx_downloads_container_id ON downloads (container_id);
CREATE INDEX IF NOT EXISTS idx_downloads_state ON downloads (state);
CREATE INDEX IF NOT EXISTS idx_downloads_start_time ON downloads (start_time DESC);
```

状态枚举（D-11）：progressing, completed, cancelled, interrupted, paused, waiting

**核心函数：**

1. `initDatabase()` — 初始化数据库连接，创建 downloads 表，设置 WAL 模式
2. `registerSessionDownloadHandler(ses, containerId)` — 在容器 Session 上注册 will-download 事件
   - will-download 回调中：
     - 读取 configStore 获取默认保存路径（默认 ~/Downloads）（D-02）
     - 调用 dialog.showSaveDialog 显示系统原生保存对话框（D-01, D-09）
     - 用户取消时调用 event.preventDefault() 并返回
     - 处理文件名冲突：getUniqueFilePath 自动添加 (1), (2) 后缀（D-04）
     - 同步调用 item.setSavePath(savePath)（必须在回调内同步调用，RESEARCH Pitfall 3）
     - 生成 downloadId（使用 crypto.randomUUID()）
     - 存入 activeDownloads Map 和 downloadMetrics Map
     - 调用 setupDownloadItemEvents 注册 DownloadItem 事件
     - 通过 BrowserWindow.webContents.send 推送 download:started 到渲染进程
3. `setupDownloadItemEvents(item, downloadId, containerId)` — 注册 DownloadItem 事件
   - item.on('updated')：计算速度（calculateSpeed），推送 download:progress
   - item.on('done')：根据 state（completed/cancelled/interrupted）保存记录，推送 download:completed
   - 完成后清理 activeDownloads 和 downloadMetrics
4. `calculateSpeed(downloadId, currentBytes)` — 滑动窗口速度计算（RESEARCH Pattern 3）
5. `getUniqueFilePath(filePath)` — 文件名冲突处理（RESEARCH Pattern 1）
6. `formatFileSize(bytes)` / `formatETA(bytesRemaining, speed)` — 格式化工具函数
7. `getDownloads(containerId)` — 查询容器的下载记录（按 start_time DESC）
8. `getActiveCount()` — 返回当前活跃下载数量
9. `getActiveDownloads()` — 返回活跃下载列表（用于 tooltip 显示）
10. `cancelDownload(downloadId)` — 取消下载
11. `pauseDownload(downloadId)` — 暂停下载（item.pause()）
12. `resumeDownload(downloadId)` — 恢复下载（item.resume()）
13. `openFile(filePath)` — 调用 shell.openPath 打开文件（DL-05）
14. `showInFolder(filePath)` — 调用 shell.showItemInFolder（DL-05）

**关键实现细节：**

- dialog.showSaveDialog 需要 BrowserWindow 实例作为父窗口，通过 windowManager.getMainWindow() 获取
- 速度计算使用滑动窗口平均，避免速度抖动（RESEARCH Pattern 3）
- getTotalBytes() 返回 0 时（Content-Length 未知），percent 设为 0，避免除零（RESEARCH Pitfall 2）
- 推送事件时需要检查 mainWindow 是否存在且未销毁

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer→IPC | 渲染进程通过 download:* 通道请求下载操作 |
| web→Session | 外部网页触发下载事件（will-download） |
| IPC→filesystem | download:open-file / download:show-in-folder 访问本地文件系统 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-30-01 | Tampering | download:open-file | high | mitigate | assertTrustedSender 校验 IPC 来源仅为主窗口；filePath 传入 shell.openPath 前不做拼接（Electron shell.openPath 不支持路径遍历到任意目录，仅打开文件） |
| T-30-02 | Elevation of Privilege | will-download | medium | accept | 下载由用户主动触发（点击链接），保存对话框由系统原生 NSSavePanel 控制，用户可选择保存位置或取消 |
| T-30-03 | Tampering | download:list | low | accept | 只读查询，assertTrustedSender 已校验来源；containerId 参数经 sanitizeContainerId 验证格式 |
| T-30-SC | Tampering | npm/pip/cargo installs | high | mitigate | 无新依赖安装，使用已有 better-sqlite3 和 electron-store |
</threat_model>
