在 search-manager.js 中新增两个函数和相关常量，实现完整的 web_fetch 内容提取管线。

**1. 新增 imports（文件顶部现有 require 之后，line 25 附近）：**
- `const { JSDOM } = require('jsdom');`
- `const { Readability } = require('@mozilla/readability');`
- `const TurndownService = require('turndown');`

**2. 新增常量（现有常量区域之后，line 67 附近）：**
- `FETCH_TIMEOUT_MS = 15_000` — web_fetch 请求超时
- `MAX_REDIRECTS = 5` — 最大重定向次数
- `FETCH_DEFAULT_MAX_LENGTH = 12_000` — 默认最大内容长度

**3. 新增 `htmlToMarkdown(html, url)` 函数（per D-01, D-02, D-03）：**
- 创建 JSDOM 实例：`new JSDOM(html, { url })`（url 参数用于 Readability 的相对链接解析）
- 用 Readability 提取正文：`new Readability(dom.window.document).parse()`
- 若 Readability 返回 null（空/不可读页面），回退使用原始 html（per FLAGGED-ASSUMPTION: FETCH-03 empty）
- 创建 TurndownService 实例，配置：`headingStyle: 'atx'`, `bulletListMarker: '-'`
- 调用 `turndown.remove(['script', 'style', 'nav', 'footer', 'aside'])` 去噪（per D-02）
- 返回 `turndown.turndown(contentHtml)` 结果
- JSDOM 实例在函数结束时自动释放（无显式 close，GC 回收 window）

**4. 新增 `fetchUrl(url, maxLength = FETCH_DEFAULT_MAX_LENGTH)` 函数（per FETCH-01~04, D-04~D-07）：**
- URL 协议白名单校验：`['http:', 'https:'].includes(parsed.protocol)`，否则抛出 `'仅支持 http/https 协议'`
- 逐跳重定向循环（per FETCH-04, D-01）：
  - `for (let hop = 0; hop <= MAX_REDIRECTS; hop++)` 循环
  - 每跳先调用 `await isPrivateHost(new URL(currentUrl).hostname)` 检查 SSRF
  - 使用 `net.fetch(currentUrl, { headers: {...}, redirect: 'manual', signal: AbortSignal.timeout(FETCH_TIMEOUT_MS) })` 发请求
  - 若响应状态 301/302/307/308，从 `res.headers.get('location')` 获取重定向目标，`new URL(loc, currentUrl).href` 解析相对路径，continue
  - 否则 break
- 若最终响应 `!res.ok`，抛出 `HTTP ${res.status}` 错误
- Content-Type 判断（per D-04）：
  - `application/json` → `JSON.stringify(JSON.parse(raw), null, 2)`，format = 'json'
  - `text/html` → `await htmlToMarkdown(raw, currentUrl)`，format = 'markdown'
  - 其他 → 原样返回 raw，format = 'text'
- 截断逻辑（per D-05, D-06）：
  - 若 `text.length > maxLength`，截断到 maxLength 字符
  - 追加 `\n\n[内容已截断，原始长度: ${text.length} 字符，已显示: ${maxLength} 字符]`
- 返回 `{ markdown: text, finalUrl: currentUrl, format, truncated }`

**5. 更新 module.exports（line 1448-1463）：**
- 新增导出：`fetchUrl`, `htmlToMarkdown`

**关键约束：**
- 所有 HTTP 请求必须使用 `net.fetch`（Electron 内置），不得使用 `fetch` 或 `axios`（per 项目规范）
- SSRF 防护复用已有的 `isPrivateHost` 函数，不得重新实现
- 重定向必须用 `redirect: 'manual'` 手动跟踪（per Pitfall 1: DNS Rebinding）
- 图片保留 Markdown 语法 `![alt](src)`（per D-03，turndown 默认行为）

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AI → search-manager | AI 调用 web_fetch 传入用户可控的 URL |
| search-manager → 外网 | net.fetch 发出的 HTTP 请求可能被重定向到内网 |
| 外网 → search-manager | 外部服务器返回的 HTML/JSON 内容可能含恶意代码 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-41-01 | Information Disclosure (SSRF) | search-manager.js:fetchUrl | critical | mitigate | isPrivateHost 逐跳校验 + redirect:manual + DNS 解析检查。重定向目标每次都重新校验，防止通过重定向跳转到内网 |
| T-41-02 | Tampering (XSS) | turndown 输出 | high | mitigate | turndown 输出为 Markdown 文本，AI 渲染时使用 DOMPurify 消毒（已有模式：marked + DOMPurify.sanitize）。本任务不直接渲染 HTML |
| T-41-03 | Information Disclosure (API Key) | electron-store | medium | accept | API Key 存储在 electron-store（realm-config.json），与项目其他敏感配置（AI provider keys）同一存储位置。不在日志中输出 Key |
| T-41-04 | Denial of Service | search-manager.js:fetchUrl | medium | mitigate | AbortSignal.timeout(15000) 限制单次请求超时，MAX_REDIRECTS=5 限制重定向次数，防止无限循环 |
| T-41-SC | Tampering | npm install jsdom turndown | high | mitigate | jsdom 和 turndown 是成熟广泛使用的 npm 包。安装前通过 `npm view` 验证版本号。阻断性人工检查点见 Plan 02 |
</threat_model>
